# 1. 왜 커스텀 도구가 필요한가

Snowflake CoWork(구 Snowflake Intelligence)의 Cortex Analyst 도구는 자연어 질문을 **SQL로 바꿔 실행**합니다. 교차표나 비율을 구하는 것까지는 SQL만으로 충분하지만, 그 차이를 검정하는 일은 다릅니다.

| 항목 | SQL만으로 처리할 때 |
|---|---|
| 교차표, 행·열 비율 | `GROUP BY`, `PIVOT`, `COUNT / SUM() OVER()`로 가능 |
| 기대빈도, χ² 통계량, z값 | 계산은 가능하지만 쿼리가 길어서 LLM이 매번 정확하게 생성하기 어려움 |
| p-value | 카이제곱 분포·정규분포의 누적분포함수가 Snowflake SQL에 기본 제공되지 않음* |
| Fisher 정확검정, 정확 이항검정 | SQL로 구현하기 어려움 |
| Cramér's V, 조정잔차, Wilson 신뢰구간 | 가능하지만 쿼리가 더 복잡해짐 |

\* 작성 시점 기준으로 확인한 내용입니다. 이후 Snowflake에 관련 함수가 추가되었을 수 있으니 공식 문서를 함께 확인하세요.

그래서 `scipy.stats`를 쓰는 **Python 저장 프로시저**를 만들고, 이를 에이전트의 custom tool로 등록하는 방식을 택했습니다.

## 이 도구로 할 수 있는 검정

| 검정 | 질문 형태 | 예시 |
|---|---|---|
| 독립성 검정 | 두 범주형 변수가 서로 관련 있는가? | 실험 그룹과 구매 여부는 관련이 있는가? |
| 동질성 검정 | 여러 집단의 범주 분포가 같은가? | A/B 그룹의 채널 이용 분포가 같은가? (계산은 독립성 검정과 같음) |
| 적합도 검정 | 관측 분포가 기대 비율과 같은가? | 방문 요일이 균등하게 분포하는가? |
| Fisher 정확검정 | 2×2 표에서 기대빈도가 작을 때 | 표본이 작은 A/B 테스트 |
| 일표본 비율 Z검정 | 비율이 특정 값과 다른가? | 구매율이 목표치 24%와 다른가? |
| 두 표본 비율 Z검정 | 두 집단의 비율이 다른가? | A안과 B안의 구매율이 다른가? |
| McNemar 검정 | 같은 대상의 전후 Y/N 비율이 달라졌는가? | 같은 고객의 구매여부가 프로모션 전후로 달라졌는가? |

### 비율 Z검정과 카이제곱 검정의 관계
두 표본 비율 Z검정과 2×2 표의 카이제곱 독립성 검정(연속성 보정 없음)은 **수학적으로 같은 검정**입니다(z² = χ²). 그래서 결론도 같습니다. 다만 비율 Z검정은 **비율 차이와 그 신뢰구간**, 그리고 **방향(어느 쪽이 큰지)** 을 바로 보여준다는 장점이 있어 A/B 테스트 보고에 더 많이 쓰입니다.

### McNemar 검정이 필요한 이유
같은 고객의 전후 구매여부처럼 **짝지어진 범주형 데이터**에 일반 카이제곱 검정을 쓰면, 관측값이 독립이라는 가정이 깨집니다. McNemar 검정은 **값이 바뀐 쌍(불일치 쌍)** 만 보고, Y→N 변화와 N→Y 변화의 개수가 같은지 검정합니다. 대응표본 t검정의 범주형 버전이라고 생각하면 됩니다.

# 2. 전체 구성

```
KWS_DB
└── STATISTICS (schema)
    ├── SAMPLE_CHISQ     -- 테스트용 범주형 샘플 테이블
    └── RUN_CHISQ(...)   -- 비율·범주 검정 Python 저장 프로시저 (VARIANT 반환)
```

동작 흐름은 다음과 같습니다.

```
사용자 질문 (CoWork)
  → 에이전트가 RUN_CHISQ 도구를 선택하고 TEST_TYPE과 파라미터를 채움
  → Snowflake에서 빈도를 집계 (GROUP BY)
  → 집계된 빈도표만 Python으로 가져와 scipy로 검정
  → JSON 결과 반환
  → 에이전트가 결과를 해석해서 답변
```

스키마는 다음과 같이 만듭니다.

```sql
CREATE SCHEMA IF NOT EXISTS KWS_DB.STATISTICS;
```

# 3. 샘플 데이터 만들기

## 3.1 시나리오

평균 비교 글과 같은 **온라인 쇼핑몰 프로모션 실험**을 범주형 관점에서 다시 봅니다.

- 고객 600명을 무작위로 **A그룹(기존안)** 과 **B그룹(신규 프로모션)** 으로 나눕니다.
- 고객별로 **프로모션 전 구매 여부**, **프로모션 후 구매 여부**, **주로 방문한 요일**, **주 이용 채널**을 기록합니다.

이렇게 구성하면 하나의 테이블로 "관련 있음"과 "관련 없음"을 모두 테스트할 수 있습니다.

| 검정 | 이 데이터에서 묻는 질문 | 설계상 정답 |
|---|---|---|
| 독립성: 그룹 × 구매여부 | 프로모션 그룹에 따라 구매율이 다른가? | **관련 있음** |
| 독립성: 그룹 × 채널 | 그룹에 따라 이용 채널 분포가 다른가? | **관련 없음** |
| 적합도: 방문요일 (균등 기준) | 요일별 방문이 균등한가? | **균등하지 않음** |
| 적합도: 방문요일 (설계 비율 기준) | 요일별 방문이 설계한 비율을 따르는가? | **따름** |
| 두 표본 비율 Z: 그룹별 구매율 | A안과 B안의 구매율이 다른가? | **다름** (B가 높음) |
| 일표본 비율 Z: 전체 구매율 | 전체 구매율이 24%와 다른가? | **다르지 않음** (기댓값 약 24%) |
| McNemar: 전후 구매여부 | 같은 고객의 구매여부가 프로모션 전후로 달라졌는가? | **달라짐** (구매 증가) |

## 3.2 테이블 구조

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `CUSTOMER_ID` | NUMBER | 고객 ID (1~600) |
| `AB_GROUP` | VARCHAR | 실험 그룹. `A`(기존안) 또는 `B`(신규 프로모션), 약 50:50 무작위 배정 |
| `PURCHASED` | VARCHAR | **프로모션 후** 구매 여부. `Y` 또는 `N` |
| `PURCHASED_BEFORE` | VARCHAR | **프로모션 전** 구매 여부. `Y` 또는 `N` (McNemar 검정용) |
| `VISIT_DAY` | VARCHAR | 주 방문 요일. `MON` ~ `SUN` |
| `CHANNEL` | VARCHAR | 주 이용 채널. `APP`, `WEB`, `STORE` |

고객 1명당 1행이므로 **전체 600행**입니다.

## 3.3 데이터 생성 규칙

| 컬럼 | 생성 규칙 | 의도 |
|---|---|---|
| `AB_GROUP` | A/B를 각각 50% 확률로 배정 | 무작위 배정 |
| `PURCHASED` | 구매확률 **A 18%, B 30%** | 그룹과 **관련 있게** 설계. 전체 기댓값은 약 24% |
| `PURCHASED_BEFORE` | 사후 구매자는 40%, 사후 비구매자는 10% 확률로 Y | 같은 고객의 전후가 **상관되게**, 그리고 전체적으로 **사후에 구매가 늘도록** 설계 |
| `VISIT_DAY` | 월~목 각 12%, 금 14%, **토·일 각 19%** | 주말에 몰리도록 **균등하지 않게** 설계 |
| `CHANNEL` | APP/WEB/STORE를 각각 1/3 확률로 배정, 그룹과 무관 | 그룹과 **관련 없게** 설계 |

## 3.4 생성 SQL

```sql
CREATE OR REPLACE TABLE KWS_DB.STATISTICS.SAMPLE_CHISQ AS
WITH c AS (
  SELECT SEQ4() + 1 AS CUSTOMER_ID,
         IFF(UNIFORM(0, 1, RANDOM()) = 0, 'A', 'B') AS AB_GROUP,
         UNIFORM(0, 99, RANDOM()) AS R_BUY,
         UNIFORM(0, 99, RANDOM()) AS R_DAY,
         UNIFORM(0, 2, RANDOM()) AS R_CH
  FROM TABLE(GENERATOR(ROWCOUNT => 600))
)
SELECT CUSTOMER_ID,
       AB_GROUP,
       IFF(R_BUY < IFF(AB_GROUP = 'B', 30, 18), 'Y', 'N') AS PURCHASED,
       CASE WHEN R_DAY < 12 THEN 'MON' WHEN R_DAY < 24 THEN 'TUE' WHEN R_DAY < 36 THEN 'WED'
            WHEN R_DAY < 48 THEN 'THU' WHEN R_DAY < 62 THEN 'FRI' WHEN R_DAY < 81 THEN 'SAT'
            ELSE 'SUN' END AS VISIT_DAY,
       DECODE(R_CH, 0, 'APP', 1, 'WEB', 'STORE') AS CHANNEL
FROM c;

-- McNemar 검정용: 프로모션 전 구매 여부 (사후 구매 여부와 상관되게 생성)
ALTER TABLE KWS_DB.STATISTICS.SAMPLE_CHISQ ADD COLUMN PURCHASED_BEFORE VARCHAR;
UPDATE KWS_DB.STATISTICS.SAMPLE_CHISQ
SET PURCHASED_BEFORE = IFF(UNIFORM(0, 99, RANDOM()) < IFF(PURCHASED = 'Y', 40, 10), 'Y', 'N');
```

`UNIFORM(0, 99, RANDOM())`으로 0~99 사이 정수를 뽑아, 그 값이 어느 구간에 들어가는지로 확률을 표현했습니다. 예를 들어 B그룹은 `R_BUY < 30`이면 구매(Y)이므로 구매확률이 30%입니다.

> **참고:** 시드 없이 `RANDOM()`을 쓰기 때문에 실행할 때마다 값이 달라집니다. 아래 수치는 필자의 실행 결과이며, 직접 실행하면 숫자는 조금씩 다르게 나옵니다. 다만 설계한 차이가 충분히 커서 결론은 대체로 같게 나옵니다.

## 3.5 생성된 데이터 요약 (필자 실행 기준)

**그룹 × 구매여부 (프로모션 후)**

| 그룹 | N | Y | 합계 | 구매율 |
|---|---|---|---|---|
| A | 253 | 51 | 304 | 16.8% |
| B | 194 | 102 | 296 | 34.5% |
| 전체 | 447 | 153 | 600 | 25.5% |

**그룹 × 채널**

| 그룹 | APP | STORE | WEB | 합계 |
|---|---|---|---|---|
| A | 101 | 100 | 103 | 304 |
| B | 92 | 107 | 97 | 296 |

**방문요일**

| MON | TUE | WED | THU | FRI | SAT | SUN | 합계 |
|---|---|---|---|---|---|---|---|
| 65 | 72 | 62 | 70 | 88 | 123 | 120 | 600 |

**프로모션 전 × 후 구매여부 (같은 고객)**

| 전 \ 후 | N | Y | 합계 |
|---|---|---|---|
| N | 397 | **91** | 488 |
| Y | **50** | 62 | 112 |
| 합계 | 447 | 153 | 600 |

굵게 표시한 칸이 **불일치 쌍**(전후 값이 바뀐 고객)입니다. N→Y 91명, Y→N 50명으로 구매가 늘어난 쪽이 많습니다.

# 4. 비율·범주 검정 프로시저 만들기

## 4.1 설계 포인트

- **네 가지 검정 유형을 하나의 도구로:** `TEST_TYPE` 파라미터로 `independence`(독립성·동질성), `goodness_of_fit`(적합도), `proportion_z`(비율 Z), `mcnemar`를 선택합니다.
- **집계는 Snowflake에서:** 원본 행을 모두 가져오지 않고 `GROUP BY`로 빈도를 집계한 뒤 빈도표만 Python으로 가져옵니다. 그래서 수억 건 테이블에서도 메모리 부담이 거의 없습니다. 평균 비교 도구와 다른 점입니다.
- **전제조건 자동 점검과 정확검정 전환:**
  - 독립성 검정: 2×2 표에 기대빈도 5 미만 셀이 있으면 **Fisher 정확검정**을 권장 검정으로 판정합니다. 그보다 큰 표에서 이런 셀이 20%를 넘으면 경고를 반환합니다.
  - 일표본 비율 Z검정: n·P0 또는 n·(1−P0)가 10 미만이면 **정확 이항검정**으로 판정합니다.
  - 두 표본 비율 Z검정: 성공·실패 수 중 하나라도 5 미만이면 **Fisher 정확검정**으로 판정합니다.
  - McNemar 검정: 불일치 쌍이 25개 미만이면 **정확검정(이항)**, 그 이상이면 **연속성 보정 카이제곱**으로 판정합니다.
- **해석에 필요한 정보:** p-value뿐 아니라 연관 강도(Cramér's V), 어느 셀이 차이를 만드는지(조정잔차), 비율 차이와 신뢰구간, 효과크기(Cohen's h)를 함께 반환합니다. 그래서 LLM이 "B그룹 구매율이 17.7%p 높다"처럼 구체적으로 설명할 수 있습니다.
- **Wilson 신뢰구간:** 비율의 신뢰구간은 단순 정규근사(Wald) 대신 Wilson 방식으로 계산합니다. 표본이 작거나 비율이 0이나 1에 가까울 때도 더 정확합니다.
- **입력 검증:** 테이블명과 컬럼명을 정규식으로 검증하고, 실제 테이블에 있는 컬럼인지 확인합니다. 쿼리는 Snowpark DataFrame API로 구성해서 SQL 인젝션을 막습니다.
- **원인을 알 수 있는 오류 메시지:** JSON 형식 오류, 필터 결과 0행, 없는 `SUCCESS_VALUE`, 범주 수가 맞지 않는 경우에 원인과 실제 값 목록을 함께 알려줍니다.
- **정확한 수치 표현:** 결과는 유효숫자 6자리로 반올림합니다. 소수 자릿수로 반올림하면 `6.75e-7` 같은 아주 작은 p-value가 모두 `0.000001`로 뭉개지기 때문입니다.

## 4.2 파라미터

| 파라미터 | 기본값 | 설명 |
|---|---|---|
| `TABLE_NAME` | (필수) | 분석할 테이블. `DB.SCHEMA.TABLE` 형식 |
| `ROW_COL` | (필수) | 첫 번째 범주형 컬럼. 아래 표 참고 |
| `COL_COL` | NULL | 두 번째 범주형 컬럼. 아래 표 참고 |
| `TEST_TYPE` | `independence` | `independence` / `goodness_of_fit` / `proportion_z` / `mcnemar` |
| `EXPECTED_PROBS` | NULL | 적합도 검정의 기대 비율. JSON 객체, 예: `{"A":0.5,"B":0.5}`. 합이 1이 아니어도 자동으로 정규화. 생략하면 균등분포 |
| `SUCCESS_VALUE` | NULL | 비율 Z검정에서 "성공"으로 셀 값 (예: `Y`). McNemar에서는 비율을 보고할 기준 값 (생략하면 정렬상 마지막 값) |
| `P0` | NULL | 일표본 비율 Z검정의 기준 비율 (0 < P0 < 1) |
| `ALPHA` | 0.05 | 유의수준 |
| `FILTER_COL`, `FILTER_VALUE` | NULL | 선택 사항. `FILTER_COL = FILTER_VALUE` 조건으로 데이터를 좁힘 |

**`TEST_TYPE`별 컬럼 지정 방법**

| `TEST_TYPE` | `ROW_COL` | `COL_COL` | 그 외 |
|---|---|---|---|
| `independence` | 첫 번째 범주 변수 | 두 번째 범주 변수 | – |
| `goodness_of_fit` | 검정할 범주 변수 | – | `EXPECTED_PROBS` (선택) |
| `proportion_z` (일표본) | 결과 변수 (예: 구매여부) | **생략** | `SUCCESS_VALUE`, `P0` |
| `proportion_z` (두 표본) | 집단 변수 (정확히 2개 값) | 결과 변수 | `SUCCESS_VALUE` |
| `mcnemar` | 전(before) 변수 | 후(after) 변수 | `SUCCESS_VALUE` (선택). 한 행 = 한 대상 |

**결과 읽는 법**

| 지표 | 해석 기준 |
|---|---|
| Cramér's V | 0.1 미만 거의 없음, 0.1~0.3 약함, 0.3~0.5 중간, 0.5 이상 강함 (도구가 `association_strength`로 함께 반환) |
| 조정잔차 / 표준화잔차 | 절댓값이 약 2(정확히는 1.96)를 넘으면 그 셀이 기대보다 유의하게 많거나(+) 적음(−) |

## 4.4 전체 코드

```sql
CREATE OR REPLACE PROCEDURE KWS_DB.STATISTICS.RUN_CHISQ(
    TABLE_NAME     VARCHAR,
    ROW_COL        VARCHAR,
    COL_COL        VARCHAR DEFAULT NULL,
    TEST_TYPE      VARCHAR DEFAULT 'independence',
    EXPECTED_PROBS VARCHAR DEFAULT NULL,
    SUCCESS_VALUE  VARCHAR DEFAULT NULL,
    P0             FLOAT   DEFAULT NULL,
    ALPHA          FLOAT   DEFAULT 0.05,
    FILTER_COL     VARCHAR DEFAULT NULL,
    FILTER_VALUE   VARCHAR DEFAULT NULL
)
RETURNS VARIANT
LANGUAGE PYTHON
RUNTIME_VERSION = '3.11'
PACKAGES = ('snowflake-snowpark-python', 'pandas', 'numpy', 'scipy')
HANDLER = 'main'
COMMENT = 'Categorical tests: chi-square independence / goodness of fit, Fisher exact, proportion Z (1 and 2 sample), McNemar'
AS
$$
import json
import math
import re

import numpy as np
import scipy
from scipy import stats
from snowflake.snowpark import Session
from snowflake.snowpark.functions import col, count, lit

_IDENT = re.compile(r'^[A-Za-z_][A-Za-z0-9_$]*$')
TYPES = ('independence', 'goodness_of_fit', 'proportion_z', 'mcnemar')


def _check_ident(name, label, parts=1):
    if name is None or name == '':
        raise ValueError(f'{label} is required')
    pieces = name.split('.')
    if len(pieces) > parts or not all(_IDENT.match(p) for p in pieces):
        raise ValueError(f'invalid {label}: {name}')
    return name.upper()


def _f(x):
    if x is None:
        return None
    x = float(x)
    return None if math.isnan(x) or math.isinf(x) else float(f'{x:.6g}')


def _decision(p, alpha):
    if p is None:
        return None
    return '유의함 (귀무가설 기각)' if p < alpha else '유의하지 않음 (귀무가설 채택)'


def _strength(v):
    if v is None:
        return None
    if v < 0.1:
        return '거의 없음'
    if v < 0.3:
        return '약함'
    if v < 0.5:
        return '중간'
    return '강함'


def _wilson(k, n, alpha):
    z = stats.norm.ppf(1 - alpha / 2)
    p = k / n
    den = 1 + z ** 2 / n
    c = (p + z ** 2 / (2 * n)) / den
    h = z * math.sqrt(p * (1 - p) / n + z ** 2 / (4 * n ** 2)) / den
    return [_f(c - h), _f(c + h)]


def _counts(df, cols_):
    agg = df.group_by(*cols_).agg(count(lit(1)).alias('N')).to_pandas()
    for c in cols_:
        agg[c] = agg[c].astype(str)
    return agg


def main(session: Session, table_name, row_col, col_col, test_type, expected_probs,
         success_value, p0, alpha, filter_col, filter_value):
    try:
        tbl = _check_ident(table_name, 'TABLE_NAME', parts=3)
        rcol = _check_ident(row_col, 'ROW_COL')
        ttype = (test_type or 'independence').strip().lower()
        alpha = 0.05 if alpha is None else float(alpha)
        if ttype not in TYPES:
            raise ValueError('TEST_TYPE must be one of: ' + ', '.join(TYPES))

        df = session.table(tbl)
        cols = set(df.columns)

        def need(name, label):
            c = _check_ident(name, label)
            if c not in cols:
                raise ValueError(f'column not found: {c}')
            return c

        need(rcol, 'ROW_COL')
        if filter_col:
            fcol = need(filter_col, 'FILTER_COL')
            df = df.filter(col(fcol) == filter_value)

        result = {'test_type': ttype, 'table': tbl, 'row_col': rcol, 'alpha': alpha,
                  'scipy_version': scipy.__version__}
        if filter_col:
            result['filter'] = {filter_col.upper(): filter_value}

        def empty_check(n):
            if n == 0:
                raise ValueError('no rows match the given conditions (check FILTER_COL/FILTER_VALUE)')

        # ---------- goodness of fit ----------
        if ttype == 'goodness_of_fit':
            agg = _counts(df.filter(col(rcol).is_not_null()), [rcol])
            empty_check(len(agg))
            observed = {k: int(v) for k, v in zip(agg[rcol], agg['N'])}
            if expected_probs:
                try:
                    probs = json.loads(expected_probs)
                except Exception:
                    raise ValueError('EXPECTED_PROBS must be valid JSON like {"A": 0.5, "B": 0.5}')
                if not isinstance(probs, dict) or not probs:
                    raise ValueError('EXPECTED_PROBS must be a JSON object like {"A": 0.5, "B": 0.5}')
                probs = {str(k): float(v) for k, v in probs.items()}
                extra = sorted(set(observed) - set(probs))
                if extra:
                    raise ValueError(f'categories missing in EXPECTED_PROBS: {extra}')
                if any(v < 0 for v in probs.values()) or sum(probs.values()) <= 0:
                    raise ValueError('EXPECTED_PROBS must be non-negative with positive sum')
                expected_basis = 'user_specified'
            else:
                probs = {k: 1.0 for k in observed}
                expected_basis = 'uniform'
            cats = sorted(probs)
            total_p = sum(probs.values())
            obs = np.array([observed.get(c, 0) for c in cats], dtype=float)
            n = obs.sum()
            if len(cats) < 2:
                raise ValueError(f'{rcol} has only 1 category; need at least 2')
            exp = np.array([probs[c] / total_p * n for c in cats])
            chi2, p = stats.chisquare(obs, exp)
            low = int((exp < 5).sum())
            result.update({
                'expected_basis': expected_basis, 'n': int(n),
                'categories': {
                    c: {'observed': int(o), 'expected': _f(e), 'observed_pct': _f(o / n * 100),
                        'std_residual': _f((o - e) / math.sqrt(e)) if e > 0 else None}
                    for c, o, e in zip(cats, obs, exp)},
                'chi2': _f(chi2), 'df': len(cats) - 1, 'p_value': _f(p),
                'expected_lt5_cells': low,
                'warning': '기대빈도 5 미만 범주가 있어 결과 신뢰도가 낮을 수 있음' if low else None,
                'decision': _decision(_f(p), alpha),
            })
            return result

        # ---------- one-sample proportion z ----------
        if ttype == 'proportion_z' and not col_col:
            if success_value is None:
                raise ValueError('SUCCESS_VALUE is required for proportion_z (e.g. "Y")')
            if p0 is None or not (0 < float(p0) < 1):
                raise ValueError('P0 (hypothesized proportion, 0 < P0 < 1) is required for one-sample proportion_z')
            p0 = float(p0)
            agg = _counts(df.filter(col(rcol).is_not_null()), [rcol])
            empty_check(len(agg))
            n = int(agg['N'].sum())
            k = int(agg.loc[agg[rcol] == str(success_value), 'N'].sum())
            ph = k / n
            z = (ph - p0) / math.sqrt(p0 * (1 - p0) / n)
            p = 2 * stats.norm.sf(abs(z))
            exact = stats.binomtest(k, n, p0)
            warn = None
            if n * p0 < 10 or n * (1 - p0) < 10:
                warn = 'n*P0 또는 n*(1-P0) < 10: 정규근사가 부정확할 수 있어 exact_binomial 결과 권장'
            result.update({
                'success_value': str(success_value), 'p0': p0, 'n': n, 'successes': k,
                'proportion': _f(ph), 'proportion_ci_wilson': _wilson(k, n, alpha),
                'z_stat': _f(z), 'p_value': _f(p),
                'exact_binomial': {'p_value': _f(exact.pvalue)},
                'recommended_test': 'exact_binomial' if warn else 'proportion_z',
                'warning': warn,
                'decision': _decision(_f(exact.pvalue if warn else p), alpha),
            })
            return result

        ccol = need(col_col, 'COL_COL')
        result['col_col'] = ccol
        base = df.filter(col(rcol).is_not_null() & col(ccol).is_not_null())

        # ---------- McNemar (paired binary: ROW_COL = before, COL_COL = after, same row = same subject) ----------
        if ttype == 'mcnemar':
            agg = _counts(base, [rcol, ccol])
            empty_check(len(agg))
            cats = sorted(set(agg[rcol]) | set(agg[ccol]))
            if len(cats) != 2:
                raise ValueError(f'McNemar needs exactly 2 shared categories in {rcol} and {ccol}; found {cats}')
            pos = str(success_value) if success_value is not None else cats[-1]
            if pos not in cats:
                raise ValueError(f'SUCCESS_VALUE {pos!r} not found; categories are {cats}')
            neg = [c for c in cats if c != pos][0]

            def cell(r, c):
                return int(agg.loc[(agg[rcol] == r) & (agg[ccol] == c), 'N'].sum())
            a, b, c_, d = cell(pos, pos), cell(pos, neg), cell(neg, pos), cell(neg, neg)
            n = a + b + c_ + d
            disc = b + c_
            if disc == 0:
                raise ValueError('no discordant pairs (no change between ROW_COL and COL_COL); McNemar is undefined')
            exact_p = stats.binomtest(min(b, c_), disc, 0.5).pvalue
            chi2_cc = (abs(b - c_) - 1) ** 2 / disc
            p_cc = stats.chi2.sf(chi2_cc, 1)
            p_before, p_after = (a + b) / n, (a + c_) / n
            rec = 'exact' if disc < 25 else 'chi2_corrected'
            result.update({
                'success_value': pos, 'n_pairs': n,
                'table': {f'{rcol}={pos}': {f'{ccol}={pos}': a, f'{ccol}={neg}': b},
                          f'{rcol}={neg}': {f'{ccol}={pos}': c_, f'{ccol}={neg}': d}},
                'discordant': {f'{pos}->{neg}': b, f'{neg}->{pos}': c_},
                'proportion_row_col': _f(p_before), 'proportion_col_col': _f(p_after),
                'proportion_change': _f(p_after - p_before),
                'odds_ratio_discordant': _f(c_ / b) if b > 0 else None,
                'exact': {'p_value': _f(exact_p)},
                'chi2_corrected': {'chi2': _f(chi2_cc), 'df': 1, 'p_value': _f(p_cc)},
                'recommended_test': rec,
                'decision': _decision(_f(exact_p if rec == 'exact' else p_cc), alpha),
            })
            return result

        agg = _counts(base, [rcol, ccol])
        empty_check(len(agg))
        table = agg.pivot_table(index=rcol, columns=ccol, values='N', aggfunc='sum', fill_value=0)
        table = table.sort_index().sort_index(axis=1)

        # ---------- two-sample proportion z (ROW_COL = group, COL_COL = outcome) ----------
        if ttype == 'proportion_z':
            if success_value is None:
                raise ValueError('SUCCESS_VALUE is required for proportion_z (e.g. "Y")')
            if table.shape[0] != 2:
                raise ValueError(f'two-sample proportion_z needs exactly 2 groups in {rcol}; found {list(table.index)} (use FILTER_COL or independence test)')
            sv = str(success_value)
            if sv not in table.columns:
                raise ValueError(f'SUCCESS_VALUE {sv!r} not found in {ccol}; values are {list(table.columns)}')
            g1, g2 = list(table.index)
            n1, n2 = int(table.loc[g1].sum()), int(table.loc[g2].sum())
            k1, k2 = int(table.loc[g1, sv]), int(table.loc[g2, sv])
            p1, p2 = k1 / n1, k2 / n2
            pp = (k1 + k2) / (n1 + n2)
            se0 = math.sqrt(pp * (1 - pp) * (1 / n1 + 1 / n2))
            if se0 == 0:
                raise ValueError('pooled proportion is 0 or 1; z-test is undefined (use Fisher exact)')
            z = (p1 - p2) / se0
            p = 2 * stats.norm.sf(abs(z))
            zc = stats.norm.ppf(1 - alpha / 2)
            se1 = math.sqrt(p1 * (1 - p1) / n1 + p2 * (1 - p2) / n2)
            h = 2 * math.asin(math.sqrt(p1)) - 2 * math.asin(math.sqrt(p2))
            small = min(k1, k2, n1 - k1, n2 - k2) < 5
            fisher_p = stats.fisher_exact([[k1, n1 - k1], [k2, n2 - k2]])[1]
            result.update({
                'success_value': sv,
                'groups': {g1: {'n': n1, 'successes': k1, 'proportion': _f(p1), 'ci_wilson': _wilson(k1, n1, alpha)},
                           g2: {'n': n2, 'successes': k2, 'proportion': _f(p2), 'ci_wilson': _wilson(k2, n2, alpha)}},
                'diff_1_minus_2': _f(p1 - p2),
                'diff_ci': [_f(p1 - p2 - zc * se1), _f(p1 - p2 + zc * se1)],
                'pooled_proportion': _f(pp),
                'z_stat': _f(z), 'p_value': _f(p),
                'cohens_h': _f(h),
                'fisher_exact': {'p_value': _f(fisher_p)},
                'recommended_test': 'fisher_exact' if small else 'proportion_z',
                'note': 'z^2 = 2x2 Pearson chi2 (보정 없음); 같은 결론',
                'decision': _decision(_f(fisher_p if small else p), alpha),
            })
            return result

        # ---------- independence ----------
        if table.shape[0] < 2 or table.shape[1] < 2:
            raise ValueError(f'each variable needs at least 2 categories; {rcol}={list(table.index)}, {ccol}={list(table.columns)}')
        obs = table.to_numpy(dtype=float)
        n = obs.sum()
        is_2x2 = obs.shape == (2, 2)
        chi2, p, dof, exp = stats.chi2_contingency(obs, correction=False)
        rows, cols_ = list(table.index), list(table.columns)
        rsum, csum = obs.sum(axis=1), obs.sum(axis=0)
        low_ratio = float((exp < 5).sum()) / exp.size
        k = min(obs.shape) - 1
        cramers_v = math.sqrt(chi2 / (n * k)) if n > 0 and k > 0 else None

        cells = {}
        for i, r in enumerate(rows):
            cells[r] = {}
            for j, c in enumerate(cols_):
                e = exp[i, j]
                denom = math.sqrt(e * (1 - rsum[i] / n) * (1 - csum[j] / n))
                cells[r][c] = {'observed': int(obs[i, j]), 'expected': _f(e),
                               'row_pct': _f(obs[i, j] / rsum[i] * 100) if rsum[i] else None,
                               'adj_residual': _f((obs[i, j] - e) / denom) if denom > 0 else None}

        result.update({
            'n': int(n), 'rows': rows, 'columns': cols_, 'cells': cells,
            'pearson': {'chi2': _f(chi2), 'df': int(dof), 'p_value': _f(p)},
            'cramers_v': _f(cramers_v), 'association_strength': _strength(cramers_v),
            'expected_lt5_ratio': _f(low_ratio),
        })
        p_rec, rec = p, 'pearson'
        if is_2x2:
            chi2_y, p_y, _, _ = stats.chi2_contingency(obs, correction=True)
            odds, p_f = stats.fisher_exact(obs.astype(int))
            result['yates'] = {'chi2': _f(chi2_y), 'df': 1, 'p_value': _f(p_y)}
            result['fisher_exact'] = {'odds_ratio': _f(odds), 'p_value': _f(p_f)}
            if low_ratio > 0:
                p_rec, rec = p_f, 'fisher_exact'
        elif low_ratio > 0.2:
            result['warning'] = '기대빈도 5 미만 셀이 20%를 넘어 카이제곱 근사가 부정확할 수 있음 (범주 병합 고려)'
        result['recommended_test'] = rec
        result['decision'] = _decision(_f(p_rec), alpha)
        return result
    except Exception as e:
        return {'error': str(e)}
$$;
```

> 2×2 표이므로 Pearson, Yates, Fisher 결과가 모두 반환됩니다. 기대빈도가 모두 5 이상이어서 Pearson 결과로 판정했고, 세 검정의 결론도 모두 같습니다.

## 5.2 독립성 검정: 그룹 × 채널

```sql
CALL KWS_DB.STATISTICS.RUN_CHISQ(
  TABLE_NAME => 'KWS_DB.STATISTICS.SAMPLE_CHISQ',
  ROW_COL => 'AB_GROUP', COL_COL => 'CHANNEL');
```

| 항목 | 값 |
|---|---|
| χ² / df / p | 0.73 / 2 / 0.694 |
| Cramér's V | 0.03 (거의 없음) |
| 조정잔차 최댓값 | 0.84 (모두 ±2 이내) |
| 판정 | **유의하지 않음** |

**해석:** 그룹에 따라 이용 채널 분포가 다르다고 볼 근거가 없습니다. 무작위 배정이 잘 되었다는 근거로도 쓸 수 있습니다. 실무에서는 이런 **사전 균형 점검(balance check)** 에 자주 쓰입니다.

## 5.3 적합도 검정: 방문요일이 균등한가

```sql
CALL KWS_DB.STATISTICS.RUN_CHISQ(
  TABLE_NAME => 'KWS_DB.STATISTICS.SAMPLE_CHISQ',
  ROW_COL => 'VISIT_DAY', TEST_TYPE => 'goodness_of_fit');
```

| 요일 | 관측 | 기대 | 표준화잔차 |
|---|---|---|---|
| MON | 65 | 85.7 | −2.24 |
| TUE | 72 | 85.7 | −1.48 |
| WED | 62 | 85.7 | −2.56 |
| THU | 70 | 85.7 | −1.70 |
| FRI | 88 | 85.7 | +0.25 |
| SAT | 123 | 85.7 | **+4.03** |
| SUN | 120 | 85.7 | **+3.70** |

| 항목 | 값 |
|---|---|
| χ² / df / p | 46.64 / 6 / 2.21 × 10⁻⁸ |
| 판정 | **유의함** (균등하지 않음) |

**해석:** 방문이 요일별로 균등하지 않습니다. 토·일요일이 기대보다 크게 많고, 월·수요일이 적습니다.

## 5.4 적합도 검정: 방문요일이 설계 비율을 따르는가

```sql
CALL KWS_DB.STATISTICS.RUN_CHISQ(
  TABLE_NAME => 'KWS_DB.STATISTICS.SAMPLE_CHISQ',
  ROW_COL => 'VISIT_DAY', TEST_TYPE => 'goodness_of_fit',
  EXPECTED_PROBS => '{"MON":0.12,"TUE":0.12,"WED":0.12,"THU":0.12,"FRI":0.14,"SAT":0.19,"SUN":0.19}');
```

| 항목 | 값 |
|---|---|
| χ² / df / p | 3.34 / 6 / 0.765 |
| 표준화잔차 범위 | −1.18 ~ +0.84 (모두 ±2 이내) |
| 판정 | **유의하지 않음** (설계 비율과 일치) |

**해석:** 관측된 요일 분포가 기대 비율과 다르다고 볼 근거가 없습니다. 같은 데이터라도 **어떤 기대분포와 비교하느냐에 따라 결론이 달라진다**는 점을 보여주는 예입니다.

## 5.5 두 표본 비율 Z검정: A안 vs B안 구매율

```sql
CALL KWS_DB.STATISTICS.RUN_CHISQ(
  TABLE_NAME => 'KWS_DB.STATISTICS.SAMPLE_CHISQ',
  ROW_COL => 'AB_GROUP', COL_COL => 'PURCHASED',
  TEST_TYPE => 'proportion_z', SUCCESS_VALUE => 'Y');
```

| 항목 | 값 |
|---|---|
| A그룹 구매율 | 16.8% (51 / 304), 95% Wilson CI: 13.0% ~ 21.4% |
| B그룹 구매율 | 34.5% (102 / 296), 95% Wilson CI: 29.3% ~ 40.0% |
| 비율 차이 (A − B) | **−17.7%p** (95% CI: −24.5%p ~ −10.8%p) |
| z / p | −4.968 / 6.75 × 10⁻⁷ |
| Cohen's h | −0.41 (작음~중간) |
| 권장 검정 | proportion_z (모든 셀이 5 이상) |
| 판정 | **유의함** |

**해석:** B안의 구매율이 A안보다 17.7%p 높고, 차이의 신뢰구간이 0을 포함하지 않으므로 통계적으로 유의합니다.

> **카이제곱 검정과의 관계 확인:** z² = (−4.968)² = 24.685로, 5.1의 Pearson χ²(24.685)와 정확히 같고 p-value도 같습니다. 같은 검정이지만 비율 Z검정은 **"몇 %p 차이인지"와 그 신뢰구간**을 바로 보여주므로, A/B 테스트 결과 보고에 더 적합합니다.

## 5.6 일표본 비율 Z검정: 전체 구매율이 24%인가

```sql
CALL KWS_DB.STATISTICS.RUN_CHISQ(
  TABLE_NAME => 'KWS_DB.STATISTICS.SAMPLE_CHISQ',
  ROW_COL => 'PURCHASED', TEST_TYPE => 'proportion_z',
  SUCCESS_VALUE => 'Y', P0 => 0.24);
```

| 항목 | 값 |
|---|---|
| 구매율 | 25.5% (153 / 600), 95% Wilson CI: 22.2% ~ 29.1% |
| z / p | 0.860 / 0.390 |
| 정확 이항검정 p | 0.390 |
| 판정 | **유의하지 않음** |

**해석:** 전체 구매율이 24%와 다르다고 볼 근거가 없습니다. 신뢰구간에 24%가 포함되며, 설계상 기댓값(약 24%)과도 일치합니다. 표본이 충분히 커서 정규근사(z)와 정확검정의 p-value가 거의 같습니다.

## 5.7 McNemar 검정: 같은 고객의 프로모션 전후 구매여부

```sql
CALL KWS_DB.STATISTICS.RUN_CHISQ(
  TABLE_NAME => 'KWS_DB.STATISTICS.SAMPLE_CHISQ',
  ROW_COL => 'PURCHASED_BEFORE', COL_COL => 'PURCHASED',
  TEST_TYPE => 'mcnemar', SUCCESS_VALUE => 'Y');
```

| 항목 | 값 |
|---|---|
| 구매율 (전 → 후) | 18.7% → 25.5% (**+6.8%p**) |
| 불일치 쌍 | N→Y **91명**, Y→N **50명** |
| 불일치 오즈비 | 1.82 |
| 연속성 보정 χ² / p | 11.35 / 0.000755 |
| 정확검정 p | 0.000699 |
| 권장 검정 | chi2_corrected (불일치 쌍 141개 ≥ 25) |
| 판정 | **유의함** |

**해석:** 같은 고객 기준으로 프로모션 후 구매율이 6.8%p 늘었고, 통계적으로 유의합니다. 구매를 새로 시작한 고객(91명)이 구매를 중단한 고객(50명)보다 약 1.8배 많습니다.

**A그룹만 보면:**
```sql
CALL KWS_DB.STATISTICS.RUN_CHISQ(
  TABLE_NAME => 'KWS_DB.STATISTICS.SAMPLE_CHISQ',
  ROW_COL => 'PURCHASED_BEFORE', COL_COL => 'PURCHASED',
  TEST_TYPE => 'mcnemar', SUCCESS_VALUE => 'Y',
  FILTER_COL => 'AB_GROUP', FILTER_VALUE => 'A');
```
불일치 쌍이 N→Y 34명, Y→N 21명이고 정확검정 p = 0.105로 **유의하지 않습니다**. 기존안(A)을 받은 고객은 전후 구매여부에 뚜렷한 변화가 없고, 전체에서 보인 증가는 주로 B그룹에서 나왔다는 뜻입니다.

> **왜 일반 카이제곱 검정을 쓰면 안 되나:** 전후 구매여부로 교차표를 만들어 독립성 검정을 하면 "전에 산 사람이 후에도 사는가"라는 **상관관계**를 검정하게 됩니다. 묻고 싶은 것은 "구매율이 **변했는가**"이므로, 바뀐 쌍만 보는 McNemar 검정이 맞습니다.

## 5.8 잘못된 입력 처리

| 입력 | 반환되는 오류 |
|---|---|
| 테이블명에 `; DROP TABLE X` | `invalid TABLE_NAME: ...` (쿼리 실행 안 됨) |
| `EXPECTED_PROBS => 'not json'` | `EXPECTED_PROBS must be valid JSON like {"A": 0.5, "B": 0.5}` |
| 필터 결과 0행 | `no rows match the given conditions (check FILTER_COL/FILTER_VALUE)` |
| 집단이 3개인 컬럼으로 두 표본 비율 Z검정 | `two-sample proportion_z needs exactly 2 groups in CHANNEL; found ['APP', 'STORE', 'WEB'] (use FILTER_COL or independence test)` |
| 없는 성공 값 `SUCCESS_VALUE => 'YES'` | `SUCCESS_VALUE 'YES' not found in PURCHASED; values are ['N', 'Y']` |
| 일표본 비율 Z검정에 `P0` 누락 | `P0 (hypothesized proportion, 0 < P0 < 1) is required for one-sample proportion_z` |
| 이진 변수가 아닌 컬럼으로 McNemar | `McNemar needs exactly 2 shared categories in ...; found [...]` |

| 검정 | 설계상 정답 | 측정 결과 | 일치 |
|---|---|---|---|

| 그룹 × 채널 | 관련 없음 | p = 0.694 | ✔ |

# 6. 에이전트에 연결할 때 팁

Cortex Agent에 custom tool로 등록할 때는 **도구 설명(description)** 이 호출 정확도를 좌우합니다. 예시는 다음과 같습니다.

```text
범주형 변수와 비율에 대한 검정을 수행한다.
카이제곱 검정, Fisher 정확검정, 비율 Z검정, McNemar 검정을 지원한다.
- 두 범주형 변수가 서로 관련 있는지, 또는 집단별 범주 분포가 같은지:
  TEST_TYPE='independence', ROW_COL과 COL_COL에 두 컬럼
- 한 범주형 변수의 분포가 균등하거나 특정 비율을 따르는지:
  TEST_TYPE='goodness_of_fit', ROW_COL에 컬럼,
  특정 비율이면 EXPECTED_PROBS에 {"범주":비율} JSON (생략하면 균등분포)
- 두 집단의 비율(전환율, 구매율 등) 차이:
  TEST_TYPE='proportion_z', ROW_COL=집단 컬럼, COL_COL=결과 컬럼, SUCCESS_VALUE=성공 값
- 비율이 특정 목표치와 다른지:
  TEST_TYPE='proportion_z', ROW_COL=결과 컬럼, COL_COL 생략, SUCCESS_VALUE, P0=목표 비율
- 같은 대상의 전후 Y/N 변화:
  TEST_TYPE='mcnemar', ROW_COL=전 컬럼, COL_COL=후 컬럼 (한 행이 한 대상이어야 함)
- 특정 기간이나 조건만 분석할 때는 FILTER_COL/FILTER_VALUE 사용
결과의 decision과 recommended_test를 기준으로 답한다.
비율 차이는 %p와 신뢰구간으로, 연관성은 cramers_v로 설명하고,
adj_residual 또는 std_residual이 ±2를 넘는 셀로 어느 범주가 차이를 만드는지 설명한다.
수치형 변수의 평균 비교에는 이 도구가 아니라 RUN_MEAN_TEST 또는 RUN_ANOVA를 사용한다.
```

함께 챙겨야 할 것들입니다.

- **평균 비교 도구와 구분:** "A/B 그룹 비교"라는 질문은 두 도구 모두에 해당할 수 있습니다. **평균 비교(구매금액)는 RUN_MEAN_TEST, 비율·분포 비교(구매 여부, 채널)는 RUN_CHISQ**라는 기준을 instructions에 명시하세요.
- **A/B 테스트 비율 비교는 `proportion_z` 우선:** 같은 결론이지만 %p 차이와 신뢰구간을 바로 설명할 수 있어 사용자가 이해하기 쉽습니다. 집단이 3개 이상이면 `independence`를 쓰게 하세요.
- **McNemar의 데이터 형태:** 이 도구는 **한 행 = 한 대상**이고 전후 값이 서로 다른 컬럼에 있는 형태(wide)를 가정합니다. 전후가 다른 행으로 나뉜 형태(long)라면 먼저 뷰로 변환해야 합니다.
- **범주 값 사전:** 에이전트가 `Y/N`, `MON~SUN` 같은 실제 값을 알아야 `SUCCESS_VALUE`나 `EXPECTED_PROBS`를 정확히 만들 수 있습니다. instructions나 시맨틱 뷰의 sample values로 알려주세요.
- **권한:** 에이전트를 사용하는 역할에 프로시저 USAGE 권한과 대상 테이블 SELECT 권한이 필요합니다.
- **범주가 너무 많은 컬럼:** 고객 ID처럼 범주가 수천 개인 컬럼으로 검정하면 의미 없는 결과가 나오고, 기대빈도 경고도 발생합니다. 범주형 컬럼만 대상으로 하도록 안내하세요.
- **인과 해석 주의:** 이 검정들은 **관련성이나 차이**를 보여줄 뿐 인과관계를 증명하지는 않습니다. 이 샘플은 무작위 배정 실험이라 인과로 해석할 수 있지만, 관찰 데이터라면 해석에 주의하도록 응답 지침에 넣는 것이 좋습니다.

# 7. 마무리

- 교차표와 비율은 SQL로 되지만, **p-value, 정확검정, 연관 강도, 잔차 분석, 비율 신뢰구간**은 Python 저장 프로시저로 해결했습니다.
- **집계는 Snowflake에서, 검정은 Python에서** 나눠서 처리해 대용량 데이터에도 쓸 수 있게 만들었습니다.
- 표본이 작을 때는 **Fisher 정확검정, 정확 이항검정, McNemar 정확검정으로 자동 전환**해서 근사 오차로 인한 잘못된 결론을 막습니다.
- 함께 쓰는 도구:
  - **1~2집단 평균 비교:** `RUN_MEAN_TEST` (t검정, Z검정, Mann-Whitney, Wilcoxon, 부호검정)
  - **세 집단 이상의 평균 비교:** `RUN_ANOVA` (분산분석, Welch ANOVA, Kruskal-Wallis, Friedman, 사후검정)
  - **전제조건 확인:** `RUN_ASSUMPTION` (정규성 검정, 등분산성 검정)
