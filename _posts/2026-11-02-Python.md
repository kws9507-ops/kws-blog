이번 주에는 Snowflake나 pandas를 아직 연결하지 않는다. **데이터를 Python 코드에서 어떻게 표현하고 꺼내는지** 먼저 익힌다.

# Day 1. 실행 환경과 첫 Python 프로그램

## 1-1. Python을 어디에서 실행할까?

- **터미널:** 명령어로 Python 프로그램을 실행한다.
- **`.py` 파일:** 실행할 Python 코드를 저장한다.
- **가상환경(`venv`):** 프로젝트별로 패키지 설치 공간을 분리한다.
- **코드 편집기:** VS Code 등으로 `.py` 파일을 작성한다.

이번 주에는 별도 패키지를 설치하지 않는다. `venv`만 준비하면 된다. Python이 아직 설치되지 않았다면 [Python 공식 설치 안내](https://www.python.org/downloads/)를 먼저 확인한다.

**버전 선택:** Python 버전은 `python --version`(Windows에서는 `py --version`도 가능)으로 확인한다. 이번 주 표준 라이브러리 실습은 일반적인 Python 3 환경을 기준으로 한다. 이후 Snowflake Connector, Snowpark, Streamlit 설치 단계에서는 **해당 라이브러리가 지원하는 Python 버전**을 공식 문서에서 확인해 선택한다.

VS Code 사용 시 프로젝트 폴더를 열고 **Python: Select Interpreter**에서 `.venv` 환경을 선택한다. 터미널에서 `python -c "import sys; print(sys.executable)"`을 실행하면 실제 사용 중인 Python 실행 파일 경로도 확인할 수 있다.

버전 또는 패키지가 프로젝트마다 충돌할 수 있으므로 가상환경 폴더 `.venv/`는 Git에 올리지 않는 편이 좋다. 프로젝트 루트의 `.gitignore` 파일에 다음을 추가한다.

__pycache__/

# Day 2. 변수와 기본 자료형

## 2-1. 변수는 데이터에 붙이는 이름

```python
order_id = "O-1001"
amount = 35000
is_paid = True

print(order_id)
print(amount)
print(is_paid)
```

SQL에서 `SELECT` 결과의 한 행을 본다고 생각해 보자. 각 컬럼의 값은 Python에서 변수로 표현할 수 있다.

| 주문 필드 | 값 예시 | Python 타입 |
|---|---|---|
| `ORDER_ID` | `"O-1001"` | `str` |
| `AMOUNT` | `35000` | `int` |
| `DISCOUNT_RATE` | `0.15` | `float` |
| `IS_PAID` | `True` | `bool` |
| `MEMO` | `None` | `NoneType` |

## 2-2. 다섯 가지 기본 값

```python
order_id = "O-1001"      # str: 텍스트
amount = 35000            # int: 정수
rate = 0.15               # float: 실수
is_paid = True            # bool: 참/거짓
memo = None               # None: 값이 없음을 나타냄

print(type(order_id))
print(type(amount))
print(type(rate))
print(type(is_paid))
print(type(memo))
```

- `None`은 문자열 `"None"`이 아니다.
- `0`, `""`(빈 문자열), `None`은 서로 다른 값이다.
- 금액처럼 정확한 합계가 필요한 값은 이번 실습에서 **정수 원 단위**로 저장한다. 실제로 소수 화폐 단위를 다룰 때는 정수 최소 단위 또는 `decimal.Decimal` 등 정확도가 적절한 타입을 고려한다.

## 2-3. 변수에 새로운 값을 대입하기

```python
amount = 35000
print(amount)

amount = 42000
print(amount)
```

같은 변수에 다시 대입하면 **변수가 가리키는 값**이 바뀐다. SQL의 테이블 업데이트와는 다른 개념이다.

## 2-4. 비교 연산자와 논리 연산자 (2주차 조건문 준비)

데이터 검증에는 두 값의 비교가 필요하다. Python에서 `=`는 대입, `==`는 같은지 비교하는 연산자다.

```python
amount = 42000
min_amount = 30000
is_paid = True

print(amount == 42000)             # True: 같다
print(amount != 42000)             # False: 다르다
print(amount > min_amount)         # True: 크다
print(amount >= min_amount)        # True: 크거나 같다
print(amount < min_amount)         # False: 작다
print(amount <= 42000)             # True: 작거나 같다

print(amount >= min_amount and is_paid)  # True
print(amount < 10000 or is_paid)         # True
print(not is_paid)                      # False
```

- `and`: 두 조건 모두 참일 때 참.
- `or`: 조건 중 하나 이상 참일 때 참.
- `not`: 참/거짓을 뒤집는다.
- **2주차**에는 이 결과를 `if` 조건문과 함께 사용한다. 이번 주에는 비교 결과를 `print()`로 확인하면 된다.

## 2-5. SQL `NULL`과 Python `None`은 비슷하지만 다르다

```python
memo = None
print(memo is None)    # True: None 여부 확인
print(memo == "")      # False: 빈 문자열과 다름
print(memo == 0)       # False: 숫자 0과 다름
print(bool(""))        # False
print(bool("False"))   # True: 빈 문자열이 아니기 때문
```

SQL의 `IS NULL`과 비교할 때 Python에서는 보통 `is None`을 사용한다. 다만 SQL의 `NULL`은 3값 논리(참/거짓/알 수 없음)와 관련되고, Python의 `None` 비교 결과는 보통 `bool`이므로 **동일한 연산 규칙이라고 생각하면 안 된다.** `bool("False")`가 `True`인 것도 자주 나오는 함정이다.

**데이터 처리 주의:** Python에서 `None`은 숫자가 아니다. `None + 1000` 또는 `sum([1000, None])`은 `TypeError`가 발생한다. SQL의 `SUM(AMOUNT)`가 NULL 값을 제외하는 것과 동작이 다르므로, Python에서 데이터를 합산하기 전에는 결측값 처리 규칙을 정해야 한다. 실제 결측값 제외 로직은 2주차 조건문·반복문에서 구현한다.

# Day 3. 문자열과 숫자 다루기

## 3-1. 문자열 연결과 f-string

```python
customer_id = "C-001"
amount = 42000

print("고객: " + customer_id)
print(f"고객 {customer_id}의 주문 금액: {amount}원")
print(f"고객 {customer_id}의 주문 금액: {amount:,}원")
```

예상 출력:

```text
고객: C-001
고객 C-001의 주문 금액: 42000원
고객 C-001의 주문 금액: 42,000원
```

`f"...{변수}..."` 형태는 문자열에 값을 끼워 넣는 문법이다. `:,`는 천 단위 구분 기호를 넣는다.

## 3-2. 문자열 인덱싱·슬라이싱

```python
order_id = "ORD-2026-001"

print(order_id[0])      # O: 첫 글자의 인덱스는 0
print(order_id[:3])     # ORD
print(order_id[-3:])    # 001
print(len(order_id))    # 문자열 길이
```

슬라이싱 `text[start:end]`는 **시작 위치는 포함하고 종료 위치는 포함하지 않는다.**

## 3-3. 자주 쓰는 문자열 메서드

```python
raw_category = "  Food  "

print(raw_category.strip())         # 앞뒤 공백 제거
print(raw_category.strip().lower()) # food

order_code = "ORD-2026-001"
print(order_code.split("-"))        # ['ORD', '2026', '001']
```

Snowflake에서 `TRIM()`, `LOWER()`, `SPLIT()`을 사용하는 것과 목적이 비슷하다.

## 3-4. 숫자 연산과 형 변환

```python
amount = 42000
quantity = 3

print(amount + 1000)    # 덧셈
print(amount * quantity) # 곱셈
print(7 / 2)            # 3.5: 일반 나눗셈
print(7 // 2)           # 3: 몫
print(7 % 2)            # 1: 나머지

raw_amount = "42000"
print(int(raw_amount) + 1000)  # 43000
print(str(amount) + "원")    # 42000원
```

> `int("42,000")`은 오류가 발생한다. 문자열에 쉼표가 있을 경우 `int("42,000".replace(",", ""))`처럼 먼저 정제해야 한다. 입력이 올바르지 않을 때의 예외 처리는 3주차에 깊게 다룬다.

## 3-5. 원시 텍스트를 숫자로 변환하고 식별자는 보존하기

```python
raw_amount = " 42,000 "
amount = int(raw_amount.strip().replace(",", ""))
print(amount + 1000)     # 43000

customer_id = "0007"
print(customer_id.zfill(6))  # 000007: 앞의 0을 보존
```

- 금액처럼 연산할 데이터는 입력을 검증·정제한 후 적절한 숫자 타입으로 바꾼다.
- 고객 ID처럼 **앞의 0도 의미가 있는 식별자**는 숫자로 바꾸지 않는다.
- `int("abc")`처럼 변환에 실패하는 경우의 `ValueError` 처리는 3주차에서 더 다룬다.

## 3-6. 실수 오차와 정확한 금액 계산

Python의 `float`는 일부 십진 소수를 이진 부동소수점으로 근사해 표현한다. 따라서 SQL의 정밀한 `NUMBER` 값과 동일하게 취급하면 금액 비교·집계에서 문제가 생길 수 있다.

```python
print(0.1 + 0.2)         # 0.30000000000000004
print(0.1 + 0.2 == 0.3)  # False

from decimal import Decimal

accurate_sum = Decimal("0.1") + Decimal("0.2")
print(accurate_sum)                 # 0.3
print(accurate_sum == Decimal("0.3"))  # True
```

- 원 단위 정수로 처리할 수 있는 실습에서는 `int`를 사용한다.
- 소수 화폐 또는 정밀도가 중요한 십진 연산에서는 `Decimal`을 고려한다.
- `Decimal(0.1)` 대신 문자열을 이용한 `Decimal("0.1")`을 사용해야 기존 `float`의 근사값을 그대로 가져오지 않는다.

본격적인 반올림 규칙과 재무 지표 정의는 데이터 분석 단계에서 다룬다. 화면 표시 형식(`:,.0f` 등)은 **숫자를 어떻게 보여줄지** 정할 뿐, 원본 숫자의 값이나 자료형을 변경하지 않는다는 점도 기억하자.

# Day 4. 리스트와 튜플

## 4-1. 리스트(`list`): 순서가 있는 여러 값

```python
amounts = [35000, 42000, 18000]

print(amounts[0])     # 35000
print(amounts[-1])    # 18000
print(amounts[:2])    # [35000, 42000]
print(len(amounts))   # 3
print(sum(amounts))   # 95000
```

리스트는 순서를 유지하며 값을 **추가·수정·삭제**할 수 있다.

```python
amounts = [35000, 42000]
amounts.append(18000)
amounts[0] = 37000

print(amounts)  # [37000, 42000, 18000]
```

`append()`는 원래 리스트를 변경한다. 반환값은 `None`이므로 `amounts = amounts.append(18000)`처럼 작성하면 안 된다.

## 4-2. 튜플(`tuple`): 변경할 수 없는 순서형 자료구조

```python
report_period = (2026, 11)

print(report_period[0])  # 2026
print(report_period[1])  # 11
```

튜플은 생성 후 항목을 수정할 수 없다.

```python
# 아래 코드는 TypeError가 발생하므로 실행하지 않는다.
# report_period[0] = 2027
```

**선택 기준:** 주문 목록처럼 항목이 늘어나고 수정될 수 있으면 `list`, 고정된 기간 쌍처럼 변경하지 않을 값은 `tuple`을 고려한다.

## 4-3. 리스트 안에 리스트가 있을 수도 있다

```python
monthly_amounts = [
    [10000, 20000],
    [30000, 40000],
]

print(monthly_amounts[0][1])  # 20000
```

실무에서는 행마다 의미가 다른 값들을 위치로 관리하기보다 **딕셔너리**를 사용하는 경우가 많다. 다음 날 학습한다.

## 4-4. 데이터 분석에 자주 쓰는 리스트 연산

```python
amounts = [35000, 42000, 18000]
print(min(amounts))                  # 18000
print(max(amounts))                  # 42000
print(sum(amounts) / len(amounts))   # 약 31666.67
print(sorted(amounts, reverse=True)) # [42000, 35000, 18000]
print(amounts)                       # 원본은 변경되지 않음

copied_amounts = amounts.copy()
copied_amounts.append(10000)
print(len(amounts))        # 3: 원본 영향 없음
print(len(copied_amounts)) # 4
```

`sorted()`는 정렬된 **새 리스트**를 만들고, `list.sort()`는 **원래 리스트**를 변경한다. `copy()`는 기본적인 얕은 복사다. 리스트 안에 또 리스트가 있으면 내부까지 독립적으로 복제되지는 않는다.

**주의:** `sum([])`은 0이지만, 빈 리스트에서 `min([])`, `max([])`는 오류가 발생하고 `sum([]) / len([])`는 0으로 나눠 오류가 발생한다. 빈 데이터에 대한 조건문 처리는 2주차에서 배운다.

**빈 데이터 실습(보충):** `min`과 `max`는 `default`를 지정해 빈 입력에서도 동작하게 할 수 있다. 단, **평균은 분모가 0이므로 별도 정책**(예: `None` 반환 또는 화면에 '데이터 없음' 표시)이 필요하다.

```python
empty_amounts = []
print(len(empty_amounts))                # 0
print(sum(empty_amounts))                # 0
print(min(empty_amounts, default=None))  # None
print(max(empty_amounts, default=None))  # None
```

Snowflake에서 행이 아예 없는 입력에 집계를 수행하면 `COUNT(*)`는 0을 반환하지만 `SUM(AMOUNT)`와 `AVG(AMOUNT)`는 `NULL`을 반환한다. 반면 Python의 `sum([])`은 0이다. 따라서 **0(합계가 0임)**과 **`None`/`NULL`(집계할 값이 없음)**을 대시보드에서 같게 취급할지 여부는 지표 정의서에서 결정한다. <https://docs.snowflake.com/en/sql-reference/functions-aggregation>

## 4-5. 변수 대입과 리스트 복사는 다르다

`=`는 리스트를 복제하지 않고 **같은 리스트를 다른 이름으로 참조**하게 만들 수 있다. 데이터를 원본과 가공본으로 나눌 때 반드시 알아야 하는 차이점이다.

```python
original = [100, 200]
alias = original        # 리스트 복사가 아니라 같은 객체 참조
alias.append(300)
print(original)         # [100, 200, 300]

independent = original.copy()
independent.append(400)
print(original)         # [100, 200, 300]
print(independent)      # [100, 200, 300, 400]
```

단, `.copy()`는 얕은 복사이므로 내부에 중첩 리스트가 있으면 내부 객체는 공유될 수 있다.

```python
original = [[100]]
shallow = original.copy()
shallow[0].append(200)
print(original)  # [[100, 200]]
```

데이터 정제 과정에서 **원본 데이터가 의도치 않게 바뀌는 버그**와 관련되므로 결과를 직접 비교해 보자.

# Day 5. 딕셔너리와 중첩 데이터

## 5-1. 딕셔너리(`dict`): 컬럼 이름과 값을 연결하기

SQL 결과의 한 행을 Python에서 표현하는 가장 직관적인 방법 중 하나다.

```python
order = {
    "order_id": "O-001",
    "customer_id": "C-001",
    "category": "식품",
    "amount": 35000,
    "status": "완료",
}

print(order["order_id"])       # O-001
print(order["amount"])         # 35000
print(order.get("coupon_code")) # None
```

- `order["amount"]`: 키가 없으면 `KeyError` 발생.
- `order.get("coupon_code")`: 키가 없으면 기본적으로 `None` 반환.
- `order.get("coupon_code", "없음")`: 키가 없으면 `"없음"` 반환.

> `get()` 결과가 `None`이라고 해서 항상 키가 없다는 뜻은 아니다. 해당 키가 실제로 존재하면서 값이 `None`일 수도 있다. 둘을 구분하려면 `"coupon_code" in order`를 사용한다.

## 5-2. 딕셔너리 수정과 중첩 구조

```python
customer = {
    "customer_id": "C-001",
    "name": "민지",
    "profile": {
        "region": "서울",
        "grade": "VIP",
    },
}

print(customer["profile"]["region"])  # 서울

customer["profile"]["grade"] = "GOLD"
print(customer["profile"]["grade"])   # GOLD
```

## 5-3. 여러 레코드 = 리스트 안에 딕셔너리

```python
orders = [
    {"order_id": "O-001", "customer_id": "C-001", "amount": 35000},
    {"order_id": "O-002", "customer_id": "C-002", "amount": 42000},
    {"order_id": "O-003", "customer_id": "C-001", "amount": 18000},
]

print(orders[0])                   # 첫 번째 주문 레코드
print(orders[1]["customer_id"])  # C-002
print(orders[2]["amount"])       # 18000
```

이 구조는 개념적으로 **테이블 = 리스트**, **행 = 딕셔너리**, **컬럼 이름 = 딕셔너리 키**에 대응한다. 실제 SQL 테이블과 메모리 구조가 동일하다는 뜻은 아니다.

## 5-4. 컬럼 목록·값 목록·키-값 쌍 조회하기

```python
order = {"order_id": "O-001", "amount": 35000, "status": "완료"}

print(list(order.keys()))     # ['order_id', 'amount', 'status']
print(list(order.values()))   # ['O-001', 35000, '완료']
print(list(order.items()))    # [('order_id', 'O-001'), ('amount', 35000), ('status', '완료')]
print("amount" in order)      # True: 키 존재 여부
print("memo" in order)        # False
```

- `keys()`: 컬럼 이름에 해당하는 키 확인.
- `values()`: 값 확인.
- `items()`: 키와 값을 함께 확인. 2주차 `for` 반복문에서 유용하다.
- `dict`에서 같은 키를 중복 정의하면 나중에 설정한 값이 이전 값을 덮어쓴다.

## 5-5. 키가 없는 경우와 값이 `None`인 경우

`dict.get(key, default)`의 기본값은 **키가 없을 때만** 사용된다. 키는 있지만 값이 `None`인 경우에는 `None`이 그대로 반환된다.

```python
order = {"order_id": "O-001", "coupon_code": None}
print(order.get("coupon_code", "없음"))  # None: 키가 존재함
print(order.get("memo", "없음"))         # 없음: 키가 없음
print("coupon_code" in order)           # True
print("memo" in order)                  # False
```

이 차이는 이후 JSON 정제, 결측값 처리, Snowflake 적재 시 중요하다.

# Day 6. 집합(`set`)과 자료구조 선택

## 6-1. 집합은 중복을 제거한다

```python
customer_ids = ["C-001", "C-002", "C-001", "C-003"]
unique_customer_ids = set(customer_ids)

print(len(customer_ids))         # 4: 전체 등장 횟수
print(len(unique_customer_ids))  # 3: 중복 제외 고객 수
```

`set`은 중복 원소를 저장하지 않는다. **표시 순서는 보장되지 않으므로** 출력 순서가 필요할 때는 `sorted()`를 사용한다.

```python
categories = {"식품", "전자기기", "식품", "생활용품"}
print(sorted(categories))  # ['생활용품', '식품', '전자기기']
```

## 6-2. 포함 여부와 집합 연산

```python
vip_customers = {"C-001", "C-003"}
buyers = {"C-001", "C-002"}

print("C-001" in vip_customers)  # True
print(vip_customers & buyers)    # 공통 고객: {'C-001'}
print(vip_customers - buyers)    # 구매하지 않은 VIP: {'C-003'}
```

SQL의 `DISTINCT`, `INTERSECT`, `EXCEPT`와 **개념적으로 유사**하지만, Python 집합은 SQL의 NULL 처리·행 구조와 동일하지 않다.

참고로 `left | right`는 합집합, `left ^ right`는 대칭차집합을 구한다. 집합은 순서를 보장하지 않으므로 화면에 출력하거나 파일로 저장할 때는 필요에 따라 `sorted()`를 사용한다.

empty_dict = {}    # 빈 딕셔너리

## 6-3. 어떤 자료구조를 쓸까?

| 요구 사항 | 우선 고려할 자료구조 | 예시 |
|---|---|---|

## 6-4. Snowflake `COUNT`와 Python 집계의 차이

Snowflake에서 `COUNT(DISTINCT CUSTOMER_ID)`는 `NULL`을 계산에서 제외하지만 Python 집합은 `None`을 하나의 고유 원소로 셀 수 있다. 또한 SQL의 `COUNT(*)`와 `COUNT(컬럼)`은 서로 다르다.

```python
customer_ids = ["C-001", None, "C-001", "C-002"]
print(len(set(customer_ids)))           # 3: None을 포함
print(len(set(customer_ids) - {None}))  # 2: None을 제외
```

동일한 데이터를 기준으로 세 가지 카운트를 비교해 본다.

```python
customer_ids = ["C-001", None, "C-001", "C-002"]
print(len(customer_ids))                            # 4 = COUNT(*)
print(len(customer_ids) - customer_ids.count(None)) # 3 = COUNT(CUSTOMER_ID)
print(len(set(customer_ids) - {None}))               # 2 = COUNT(DISTINCT CUSTOMER_ID)
```

```sql
SELECT
    COUNT(*) AS ROW_COUNT,
    COUNT(CUSTOMER_ID) AS NOT_NULL_COUNT,
    COUNT(DISTINCT CUSTOMER_ID) AS UNIQUE_CUSTOMER_COUNT
FROM (VALUES
    ('C-001'), (NULL), ('C-001'), ('C-002')
) AS T(CUSTOMER_ID);
-- 각각 4, 3, 2
```

이 예제처럼 단순한 식별자 값에 `None`이 들어 있을 때는 비교가 직관적이다. 실제로는 **결측값 포함 여부, 행의 집계 단위, 필터 조건**, 데이터 적재 후의 `NULL` 표현까지 함께 확인해야 한다.

## 7-3. `assert`로 결과 자동 검증하기

화면에 출력된 숫자를 눈으로만 확인하지 않고 **정답 기준을 코드로 검증**해 보자. 보통 실행에서 `assert`의 조건이 `False`면 `AssertionError`가 발생한다. 다만 `python -O`처럼 최적화 옵션을 사용하면 `assert`는 실행되지 않는다. 따라서 **학습용 확인 및 테스트용으로 사용하고, 운영 중 반드시 적용되어야 하는 데이터 품질 검증에 `assert`만 사용하면 안 된다.**

`week01_project.py`의 맨 아래에 다음 코드를 덧붙여 실행한다.

```python
assert order_count == 4
assert total_amount == 127000
assert average_amount == 31750
assert min_amount == 18000
assert max_amount == 42000
assert unique_customer_count == 3
assert len(unique_categories) == 3

print("검증 완료: 모든 집계 결과가 예상값과 일치합니다.")
```

Day 7 도전 문제에서 주문을 추가하면 일부 기준값이 달라지므로, 해당 테스트도 새로운 정답에 맞게 갱신해야 한다. `pytest`를 사용한 단위 테스트와 운영 중 오류 처리(`raise ValueError` 등)는 이후 운영 코드 학습에서 다룬다.

확인용으로 다음 명령을 각각 실행하면 차이를 관찰할 수 있다. 첫 번째는 `AssertionError`가 발생하고, 두 번째는 조용히 종료된다. **최적화 옵션에서는 검사가 생략되는 점**이 핵심이다.

```bash
python -c "assert False"
python -O -c "assert False"
```

운영 중 반드시 검증해야 할 규칙은 이후 학습할 `if` 조건문으로 명시적으로 검사하고, 위반 시 예외를 발생시키는 방법 등을 사용한다.

## 7-4. SQL 관점에서 이해하기

동일한 주문 데이터가 Snowflake 테이블 `ORDERS`에 저장돼 있다고 가정하면 다음 SQL과 의도가 비슷하다.

```sql
SELECT
    COUNT(*) AS ORDER_ROW_COUNT,
    COUNT(DISTINCT ORDER_ID) AS UNIQUE_ORDER_COUNT,
    SUM(AMOUNT) AS TOTAL_AMOUNT,
    AVG(AMOUNT) AS AVERAGE_AMOUNT,
    MIN(AMOUNT) AS MIN_AMOUNT,
    MAX(AMOUNT) AS MAX_AMOUNT,
    COUNT(DISTINCT CUSTOMER_ID) AS UNIQUE_CUSTOMER_COUNT
FROM ORDERS;
```

이번 Python 프로젝트는 **컬렉션 다루기 연습**이 목적이다. 데이터가 수백만 건이면 행을 하나씩 로컬로 내려받아 이렇게 계산하기보다 Snowflake에서 SQL 집계하는 것이 일반적으로 합리적이다.

**데이터 분석에서 중요한 해석:** 주문 건수는 4건이지만 고유 고객은 3명이므로 서로 다른 지표다. 평균 주문 금액은 `총 주문 금액 / 주문 건수`이며, 고객당 평균 매출과는 다른 계산이다. 이 차이는 이후 KPI 정의서와 대시보드 제작에서 계속 사용한다.

**집계 단위 주의:** 이 코드의 `len(orders)`는 **주문 ID 중복 여부를 확인하지 않은 '레코드 행 수'**다. 같은 `order_id`가 여러 행에 나타나는 주문상세 데이터라면 실제 주문 수와 다를 수 있다. 주문 ID가 유효하고 NULL이 없다는 전제라면 `COUNT(DISTINCT ORDER_ID)`에 해당하는 Python 계산은 `len(set(order_ids))`다.

```python
order_ids = ["O-001", "O-001", "O-002"]
print(len(order_ids))       # 3: 레코드 행 수
print(len(set(order_ids)))  # 2: 고유 주문 ID 수
```

또한 `amount`에 `None`이 섞이면 현재 Python의 `sum(amounts)`는 오류를 내지만 Snowflake의 `SUM`·`AVG`는 NULL을 제외한다. **테이블의 행 단위, 취소 주문 제외 여부, 결측값 규칙을 먼저 정해야 한다.**

모든 주문 금액이 숫자로 입력된 이 예제에서는 Python과 SQL의 집계 결과가 일치한다. `NULL`, 취소 주문, 중복 주문이 포함되면 **대상 행과 결측값 처리 규칙부터 정의**해야 한다.

# 자주 발생하는 오류와 해결

| 오류·증상 | 흔한 원인 | 해결 |
|---|---|---|
| `python: command not found` | Python 설치나 PATH 문제 | 운영체제에 맞게 `python3`, `py` 사용 여부 확인 |
| `SyntaxError` | 따옴표·괄호 누락, 잘못된 문법 | 오류 줄과 직전 줄 확인 |
| `NameError` | 변수 이름 오타 또는 변수 미정의 | 변수 이름과 대소문자 확인 |
| `TypeError` | 자료형에 맞지 않는 연산 | `type()`으로 값의 타입 확인 |
| `KeyError` | 딕셔너리에 없는 키를 `[]`로 조회 | 실제 키 확인, 필요하면 `get()` 사용 |
| `IndexError` | 리스트 범위를 벗어난 인덱스 | `len()`으로 길이 확인 |
| `ValueError` | 잘못된 문자열을 숫자로 변환 | 입력값을 검사하고 정제 |
| 한글 출력 깨짐 | 편집기·터미널 인코딩 문제 | 소스 파일 UTF-8 저장, 터미널 설정 확인 |

**디버깅 기본 습관:** 오류 메시지 마지막 줄 읽기 → 오류가 난 파일·줄 확인 → 관련 변수 `print()` 및 `type()` 확인 → 한 번에 한 부분만 수정.
