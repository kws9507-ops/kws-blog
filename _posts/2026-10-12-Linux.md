Linux 서버를 관리하면서 자주 사용하는 명령어를 정리한다.

이번 글에서는 Linux의 기본적인 디렉터리 이동부터 파일 관리, 권한 설정, 프로세스 확인, CPU 및 메모리 점검, 디스크 사용량 확인, 네트워크 연결 확인, 로그 분석, 압축 및 파일 전송까지 실무에서 자주 사용하는 명령어를 살펴본다.

특히 데이터베이스 서버를 운영하거나 Oracle, SharePlex와 같은 솔루션을 관리할 때 활용할 수 있는 명령어와 장애 발생 시 점검 순서도 함께 정리한다.

# 1. Linux란?

**Linux는 서버, PC, 클라우드 환경 등에서 널리 사용되는 오픈소스 운영체제 커널**이다.

Linux 기반 운영체제에서는 명령어를 사용해 파일과 디렉터리를 관리하고, 프로세스를 확인하거나 네트워크 상태를 점검할 수 있다.

예를 들어 서버에서 문제가 발생했을 때 다음과 같은 순서로 원인을 분석할 수 있다.

```text
서버 접속
   ↓
시스템 상태 확인
   ↓
CPU 및 메모리 점검
   ↓
디스크 사용량 확인
   ↓
프로세스 및 네트워크 확인
   ↓
로그 분석
   ↓
문제 원인 파악
```

Linux 명령어를 익혀 두면 서버 장애를 분석하거나 데이터베이스 운영 작업을 수행할 때 도움이 된다.

# 2. Linux 터미널이란?

Linux 터미널은 명령어를 입력하고 실행 결과를 확인하는 인터페이스다.

예를 들어 다음과 같이 명령어를 입력할 수 있다.

```bash
pwd
```

실행 결과:

```text
/home/oracle
```

현재 작업 중인 디렉터리의 경로를 확인할 수 있다.

명령어를 실행하면 결과가 출력되거나 파일 생성, 디렉터리 이동, 프로세스 확인 등의 작업이 수행된다.

# 3. 서버 기본 정보 확인

서버에 접속하면 먼저 호스트명, IP 주소, OS 버전, 가동 시간, 시스템 시간 등을 확인할 수 있다.

## 3.1 `hostname` - 서버 호스트명 확인

현재 서버의 호스트명을 확인한다.

```bash
hostname
```

## 3.2 `hostname -I` - 서버 IP 주소 확인

서버에 설정된 IP 주소를 확인한다.

```bash
hostname -I
```

네트워크 인터페이스별 상세 정보가 필요하면 `ip addr` 명령어를 사용할 수 있다.

## 3.3 `uname -a` - 시스템 정보 확인

커널 버전과 시스템 아키텍처 등 시스템 정보를 확인한다.

```bash
uname -a
```

## 3.4 `cat /etc/os-release` - OS 버전 확인

Linux 배포판과 버전을 확인한다.

```bash
cat /etc/os-release
```

실행 결과 예시:

```text
NAME="Oracle Linux Server"
VERSION="7.9"
ID="ol"
```

## 3.5 `uptime` - 서버 가동 시간 및 부하 확인

서버 가동 시간과 시스템 부하 평균을 확인한다.

```bash
uptime
```

실행 결과 예시:

```text
09:30:00 up 15 days, 3:20, 2 users, load average: 0.15, 0.20, 0.18
```

`load average`는 최근 1분, 5분, 15분간의 시스템 부하 평균이다.

부하가 높다고 반드시 CPU 사용률이 높은 것은 아니므로 CPU 코어 수와 프로세스 상태를 함께 확인해야 한다.

## 3.6 `date` - 현재 서버 시간 확인

현재 서버의 날짜와 시간을 확인한다.

```bash
date
```

## 3.7 `timedatectl` - 시간대 및 시간 동기화 확인

시스템 시간대와 시간 동기화 관련 상태를 확인한다.

```bash
timedatectl
```

서버 간 통신 오류나 로그 시각 불일치가 발생하면 Source, Target, Manager 서버의 시간과 동기화 상태를 비교할 때 활용할 수 있다.

## 3.8 `who`, `w`, `last` - 로그인 사용자 확인

현재 로그인한 사용자와 로그인 이력을 확인한다.

```bash
who
w
last
```

- `who`: 현재 로그인한 사용자 확인
- `w`: 로그인 사용자와 시스템 부하 확인
- `last`: 로그인 및 재부팅 이력 확인

# 4. 현재 위치 및 디렉터리 관리

## 4.1 `pwd` - 현재 경로 확인

현재 작업 중인 디렉터리의 절대 경로를 출력한다.

```bash
pwd
```

실행 결과:

```text
/home/oracle
```

현재 어느 디렉터리에서 작업하고 있는지 확인할 때 사용한다.

## 4.2 `ls` - 파일 및 디렉터리 목록 확인

현재 디렉터리에 존재하는 파일과 디렉터리를 확인한다.

```bash
ls
ls -l
ls -al
ls -lh
ls -alh
```

주요 옵션은 다음과 같다.

| 옵션 | 설명 |
| --- | --- |
| `-l` | 파일 권한, 소유자, 크기 등 상세 정보 출력 |
| `-a` | 숨김 파일 포함 |
| `-h` | 파일 크기를 읽기 쉬운 단위로 표시 |

예를 들어 `ls -alh`를 실행하면 숨김 파일을 포함한 상세 목록을 확인할 수 있다.

## 4.3 `cd` - 디렉터리 이동

다른 디렉터리로 이동할 때 사용한다.

```bash
cd /home/oracle
cd ..
cd ~
```

- `/home/oracle`: 지정한 경로로 이동
- `..`: 상위 디렉터리로 이동
- `~`: 현재 사용자의 홈 디렉터리로 이동

## 4.4 `mkdir` - 디렉터리 생성

새로운 디렉터리를 생성한다.

```bash
mkdir backup
mkdir -p /home/oracle/backup/data
```

`-p` 옵션을 사용하면 필요한 상위 디렉터리도 함께 생성한다.

## 4.5 `touch` - 파일 생성

빈 파일을 생성하거나 기존 파일의 수정 시간을 변경한다.

```bash
touch test.txt
```

파일이 존재하지 않으면 새 파일이 생성된다.

## 4.6 `which` - 명령어 경로 확인

명령어가 `PATH` 환경변수에 설정된 경로에서 어디에 위치하는지 확인한다.

```bash
which sqlplus
which sp_ctrl
```

명령어가 검색되지 않는다면 설치 여부와 `PATH` 환경변수를 확인할 수 있다.

# 5. 파일 내용 확인

## 5.1 `cat` - 파일 내용 출력

파일의 전체 내용을 출력한다.

```bash
cat test.txt
cat /etc/hosts
```

설정 파일이나 짧은 텍스트 파일의 내용을 확인할 때 사용한다.

## 5.2 `less` - 파일 내용 페이지 단위로 확인

내용이 긴 파일을 페이지 단위로 확인한다.

```bash
less application.log
```

주요 조작 방법:

| 키 | 기능 |
| --- | --- |
| `Space` | 다음 페이지 |
| `b` | 이전 페이지 |
| `/ERROR` | ERROR 검색 |
| `n` | 다음 검색 결과 |
| `N` | 이전 검색 결과 |
| `g` | 파일 처음으로 이동 |
| `G` | 파일 마지막으로 이동 |
| `q` | 종료 |

로그 파일이 크거나 설정 파일에서 특정 내용을 찾아야 할 때 유용하다.

## 5.3 `head` - 파일 앞부분 확인

파일의 첫 부분을 출력한다.

```bash
head application.log
head -n 20 application.log
```

기본적으로 앞부분 10줄을 출력하며 `-n` 옵션으로 줄 수를 지정할 수 있다.

## 5.4 `tail` - 파일 마지막 부분 확인

파일의 마지막 부분을 출력한다.

```bash
tail application.log
tail -n 100 application.log
tail -f application.log
tail -F application.log
```

- `-n 100`: 마지막 100줄 출력
- `-f`: 파일에 추가되는 내용을 실시간으로 확인
- `-F`: 로그 파일이 교체되거나 재생성되는 상황에서도 파일 추적을 시도

프로그램이 실행되는 동안 로그가 어떻게 쌓이는지 확인하려면 `tail -f`를 사용한다.

종료하려면 `Ctrl + C`를 누른다.

# 6. 파일 복사, 이동 및 삭제

## 6.1 `cp` - 파일 및 디렉터리 복사

파일이나 디렉터리를 복사한다.

```bash
cp source.txt backup.txt
cp -p source.txt backup.txt
cp -r source_dir backup_dir
```

- `cp source.txt backup.txt`: 파일 복사
- `cp -p`: 파일 속성 보존
- `cp -r`: 디렉터리와 하위 내용 복사

## 6.2 `mv` - 파일 이동 및 이름 변경

파일을 이동하거나 이름을 변경한다.

```bash
mv old.txt new.txt
mv backup.txt /home/oracle/
```

파일 이름 변경과 디렉터리 이동 모두 `mv` 명령어로 처리할 수 있다.

## 6.3 `rm` - 파일 및 디렉터리 삭제

파일이나 디렉터리를 삭제한다.

```bash
rm -i test.txt
rm -r test_dir
```

- `-i`: 삭제 전 확인
- `-r`: 디렉터리와 하위 내용 삭제

**주의:** `rm -rf`는 확인 없이 파일이나 디렉터리를 강제로 삭제할 수 있다. 운영 서버에서는 삭제 대상 경로와 파일 사용 여부를 반드시 확인해야 한다.

# 7. 파일 검색 및 내용 검색

## 7.1 `find` - 파일 및 디렉터리 검색

특정 경로에서 조건에 맞는 파일을 검색한다.

```bash
find /home/oracle -name "*.log"
find /home/oracle -type f -name "*.log"
find /home/oracle -type d -name "backup"
```

주요 옵션:

| 옵션 | 설명 |
| --- | --- |
| `-name` | 파일 또는 디렉터리 이름으로 검색 |
| `-type f` | 일반 파일만 검색 |
| `-type d` | 디렉터리만 검색 |
| `-size +1G` | 1GB를 초과하는 파일 검색 |
| `-mtime -1` | 최근 24시간 이내에 수정된 파일 검색 |
| `-mmin -1440` | 최근 1,440분 이내에 수정된 파일 검색 |

예를 들어 용량이 큰 파일을 찾으려면 다음과 같이 실행한다.

```bash
find /home -type f -size +1G
```

최근 24시간 이내에 수정된 파일을 검색하려면 다음과 같이 실행한다.

```bash
find /home -type f -mmin -1440
```

## 7.2 `grep` - 파일 내용 검색

파일 내부에서 특정 문자열을 검색한다.

```bash
grep "ERROR" application.log
grep -i "error" application.log
grep -n "ORA-" application.log
grep -in "ORA-" application.log
grep -C 5 "ERROR" application.log
```

주요 옵션:

| 옵션 | 설명 |
| --- | --- |
| `-i` | 대소문자 구분 없이 검색 |
| `-n` | 검색된 줄 번호 표시 |
| `-r` | 하위 디렉터리까지 재귀 검색 |
| `-C 5` | 검색 결과 앞뒤 5줄 표시 |

Oracle 오류 코드가 포함된 로그를 찾는 경우:

```bash
grep -in -C 5 "ORA-" application.log
```

오류가 발생한 위치뿐 아니라 주변 로그까지 확인할 수 있다.

## 7.3 `grep`과 파이프를 이용한 검색

파이프(`|`)는 앞 명령어의 결과를 뒤 명령어의 입력으로 전달한다.

예를 들어 실시간 로그에서 오류가 포함된 줄만 확인하려면 다음과 같이 실행한다.

```bash
tail -f application.log | grep --line-buffered -i "error"
```

로그가 추가될 때 ERROR가 포함된 줄을 실시간으로 확인할 수 있다.

# 8. 파일 권한 및 소유자 관리

Linux에서는 파일마다 읽기, 쓰기, 실행 권한을 설정할 수 있다.

권한 설정이 잘못되면 애플리케이션이 파일을 읽거나 쓰지 못할 수 있다.

## 8.1 `ls -l` - 권한 확인

```bash
ls -l test.txt
```

실행 결과 예시:

```text
-rw-r----- 1 oracle oinstall 1024 Oct 13 09:00 test.txt
```

권한은 다음과 같이 해석할 수 있다.

```text
-    rw-    r--    ---
     소유자   그룹   기타 사용자
```

- `r`: 읽기
- `w`: 쓰기
- `x`: 실행 또는 디렉터리 접근
- `-`: 해당 권한 없음

## 8.2 `chmod` - 권한 변경

파일 또는 디렉터리의 권한을 변경한다.

```bash
chmod 755 script.sh
chmod 644 config.txt
chmod 640 test.txt
```

권한 숫자의 의미:

| 숫자 | 권한 | 의미 |
| --- | --- | --- |
| `4` | `r--` | 읽기 |
| `2` | `-w-` | 쓰기 |
| `1` | `--x` | 실행 |
| `7` | `rwx` | 읽기, 쓰기, 실행 |
| `6` | `rw-` | 읽기, 쓰기 |
| `5` | `r-x` | 읽기, 실행 |
| `0` | `---` | 권한 없음 |

예를 들어 `chmod 755 script.sh`는 소유자에게 읽기, 쓰기, 실행 권한을 부여하고 그룹과 기타 사용자에게 읽기 및 실행 권한을 부여한다.

## 8.3 `chown` - 소유자 및 그룹 변경

파일이나 디렉터리의 소유자와 그룹을 변경한다.

```bash
chown oracle:oinstall test.txt
chown -R oracle:oinstall /home/oracle/backup
```

- `oracle`: 변경할 소유자
- `oinstall`: 변경할 그룹
- `-R`: 하위 파일 및 디렉터리까지 적용

## 8.4 `stat` - 파일 상세 정보 확인

파일의 권한, 소유자, 크기, 시간 정보를 확인한다.

```bash
stat test.txt
```

## 8.5 `id`와 `groups` - 사용자 및 그룹 확인

현재 사용자 정보를 확인한다.

```bash
whoami
id
groups
```

특정 사용자의 정보를 확인하려면 다음과 같이 실행한다.

```bash
id oracle
groups oracle
```

## 8.6 `umask` - 기본 권한 마스크 확인

새 파일과 디렉터리가 생성될 때 적용되는 기본 권한 마스크를 확인한다.

```bash
umask
```

## 8.7 `sudo` - 관리자 권한으로 명령 실행

현재 사용자에게 허용된 범위에서 관리자 권한으로 명령어를 실행한다.

```bash
sudo ls /root
sudo systemctl status sshd
sudo -l
```

`sudo -l`은 현재 사용자에게 허용된 sudo 명령을 확인한다.

운영 서버에서는 편의상 모든 권한을 부여하기보다 필요한 사용자와 그룹에 최소 권한을 부여하는 것이 중요하다.

# 9. CPU 및 메모리 사용량 확인

CPU와 메모리는 서버 성능과 관련된 주요 자원이다.

CPU 사용률이 높거나 메모리가 부족하면 애플리케이션 처리 지연이나 시스템 성능 저하가 발생할 수 있다.

## 9.1 `top` - 실시간 시스템 상태 확인

CPU, 메모리 및 프로세스별 자원 사용량을 확인한다.

```bash
top
```

주요 키:

| 키 | 설명 |
| --- | --- |
| `P` | CPU 사용률 기준 정렬 |
| `M` | 메모리 사용률 기준 정렬 |
| `1` | CPU 코어별 사용률 표시 |
| `q` | 종료 |

## 9.2 `free -h` - 메모리 사용량 확인

시스템의 메모리와 Swap 사용량을 확인한다.

```bash
free -h
```

주요 항목:

| 항목 | 설명 |
| --- | --- |
| `total` | 전체 메모리 |
| `used` | 사용 중인 메모리 |
| `free` | 사용되지 않는 메모리 |
| `buff/cache` | 버퍼 및 캐시 메모리 |
| `available` | 애플리케이션에서 추가로 사용할 수 있을 것으로 예상되는 메모리 |

Linux는 남는 메모리를 캐시로 활용하므로 `free` 값만으로 메모리 부족 여부를 판단하지 않는 것이 좋다.

## 9.3 `lscpu` - CPU 정보 확인

CPU 모델, 코어 수, 스레드 수 등을 확인한다.

```bash
lscpu
```

## 9.4 `vmstat` - 시스템 자원 통계 확인

CPU, 메모리, Swap, 프로세스 및 I/O 관련 통계를 확인한다.

```bash
vmstat 1
```

1초 간격으로 통계를 출력한다.

`si`, `so` 항목을 통해 Swap 입출력이 발생하는지 확인할 수 있다. 지속적인 Swap 사용이 보이면 메모리 상황을 추가로 점검해야 한다.

## 9.5 `ps`로 자원 사용량이 높은 프로세스 확인

CPU 사용률이 높은 프로세스를 확인한다.

```bash
ps -eo pid,ppid,user,%cpu,%mem,cmd --sort=-%cpu | head
```

메모리 사용률이 높은 프로세스를 확인한다.

```bash
ps -eo pid,user,%mem,rss,cmd --sort=-%mem | head
```

특정 프로세스가 시스템 자원을 과도하게 사용하는지 확인할 때 활용할 수 있다.

# 10. 디스크 및 파일시스템 관리

디스크 공간이 부족하면 로그 파일 생성 실패, 데이터 적재 실패, 애플리케이션 오류 등이 발생할 수 있다.

특히 데이터베이스 서버에서는 데이터 파일, 아카이브 로그, 백업 파일의 사용량을 주기적으로 확인하는 것이 중요하다.

## 10.1 `df -h` - 파일시스템 사용량 확인

```bash
df -h
df -h /home
```

주요 항목:

| 항목 | 설명 |
| --- | --- |
| `Size` | 전체 용량 |
| `Used` | 사용 중인 용량 |
| `Avail` | 사용 가능한 용량 |
| `Use%` | 사용률 |
| `Mounted on` | 마운트 경로 |

## 10.2 `df -i` - inode 사용량 확인

```bash
df -i
```

inode는 파일과 디렉터리의 메타데이터를 관리하는 자료구조다.

디스크 공간이 남아 있어도 inode가 모두 소진되면 새 파일을 생성하지 못할 수 있다.

## 10.3 `du` - 디렉터리별 용량 확인

특정 디렉터리의 전체 용량을 확인한다.

```bash
du -sh /home/oracle
du -sh /home/oracle/*
```

하위 디렉터리별 용량을 확인하려면 다음과 같이 실행할 수 있다.

```bash
du -h --max-depth=1 /home/oracle
```

## 10.4 `lsblk` - 디스크 및 파티션 확인

```bash
lsblk
```

시스템의 디스크, 파티션 및 장치 구조를 확인한다.

## 10.5 `mount`와 `findmnt` - 마운트 정보 확인

```bash
mount
findmnt
```

파일시스템이 어느 경로에 마운트되어 있는지 확인할 수 있다.

## 10.6 디스크 부족 시 점검

```bash
df -h
df -i
du -h --max-depth=1 /home
find /home -type f -size +1G
```

위 명령어를 활용하면 파일시스템 사용률, inode 부족 여부, 디렉터리별 용량 및 대용량 파일을 단계적으로 확인할 수 있다.

단, 데이터베이스 파일이나 복제 제품의 로그 파일은 사용 여부와 보존 정책을 확인하지 않고 임의로 삭제하지 않아야 한다.

# 11. 프로세스 확인 및 관리

프로세스는 현재 실행 중인 프로그램을 의미한다.

서버 운영 중 서비스가 정상적으로 실행되고 있는지, 특정 프로세스가 과도한 자원을 사용하고 있는지 확인할 때 사용한다.

## 11.1 `ps -ef` - 프로세스 목록 확인

```bash
ps -ef
ps -ef | grep oracle
ps -ef | grep pmon
```

Oracle 데이터베이스의 PMON 프로세스나 특정 프로그램이 실행 중인지 확인할 때 활용할 수 있다.

검색 명령어 자체가 결과에 포함되는 것을 줄이려면 다음과 같이 사용할 수 있다.

```bash
ps -ef | grep '[o]ra_pmon'
```

## 11.2 `pgrep` - 프로세스 검색

프로세스 이름을 기준으로 PID와 실행 명령을 확인한다.

```bash
pgrep -af sp_cop
```

## 11.3 `pstree` - 프로세스 관계 확인

프로세스의 부모·자식 관계를 확인한다.

```bash
pstree -p
```

## 11.4 `kill` - 프로세스 종료 신호 전달

특정 PID에 종료 신호를 전달한다.

```bash
kill -15 12345
```

`kill -15`는 SIGTERM 신호를 보내 프로세스가 정상적으로 종료할 기회를 준다.

강제 종료가 필요한 경우 다음 명령어를 사용할 수 있다.

```bash
kill -9 12345
```

`kill -9`는 SIGKILL 신호를 사용하므로 프로세스가 정상적인 종료 처리를 수행할 수 없다.

운영 중인 데이터베이스나 복제 솔루션의 프로세스를 종료할 때는 제품에서 제공하는 정상 종료 절차를 우선 적용해야 한다.

## 11.5 `nohup` - 터미널 종료 후에도 명령 실행 유지

터미널 세션이 종료되어도 명령이 계속 실행되도록 실행할 때 사용한다.

```bash
nohup ./script.sh &
```

## 11.6 `jobs -l` - 현재 셸의 백그라운드 작업 확인

```bash
jobs -l
```

현재 셸에서 실행한 백그라운드 작업의 상태와 PID를 확인할 수 있다.

# 12. 네트워크 및 포트 확인

서버 간 통신이 필요한 환경에서는 IP 주소, 라우팅, 포트 상태 및 연결 가능 여부를 확인해야 한다.

Oracle 데이터베이스나 SharePlex처럼 다른 서버와 통신하는 프로그램을 운영할 때 특히 중요하다.

## 12.1 `ip addr` - 네트워크 인터페이스 및 IP 확인

```bash
ip addr
```

## 12.2 `ip route` - 라우팅 정보 확인

```bash
ip route
```

## 12.3 `ping` - 네트워크 응답 확인

대상 서버에 ICMP 요청을 보내 응답 여부를 확인한다.

```bash
ping 192.168.3.112
```

응답이 없더라도 ICMP 차단이나 방화벽 정책 때문일 수 있으므로 네트워크 연결이 완전히 끊겼다고 단정할 수는 없다.

## 12.4 `getent hosts` - 호스트명 해석 확인

호스트명이 IP 주소로 정상적으로 해석되는지 확인한다.

```bash
getent hosts oracle1
```

## 12.5 `/etc/hosts` - 로컬 호스트명 매핑 확인

```bash
cat /etc/hosts
```

서버에 설정된 호스트명과 IP 주소의 매핑 정보를 확인한다.

## 12.6 `ss` - 포트 및 소켓 확인

현재 대기 중인 포트와 네트워크 소켓을 확인한다.

```bash
ss -lntp
ss -lntp | grep 2100
ss -antp
```

주요 옵션:

| 옵션 | 설명 |
| --- | --- |
| `-l` | 대기 중인 소켓 |
| `-n` | 숫자 형태로 주소와 포트 표시 |
| `-t` | TCP 소켓 |
| `-a` | 전체 관련 소켓 표시 |
| `-p` | 관련 프로세스 정보 |

SharePlex에서 사용하는 포트가 LISTEN 상태인지 확인할 때 활용할 수 있다.

## 12.7 `nc` - TCP 포트 연결 테스트

대상 서버의 특정 TCP 포트에 연결할 수 있는지 확인한다.

```bash
nc -zv 192.168.3.112 2100
```

대상 IP와 포트에 연결할 수 있는지 확인할 때 사용한다.

연결 실패만으로 방화벽이 원인이라고 확정할 수는 없다. 서비스 상태, 라우팅, 방화벽 정책 등을 함께 확인해야 한다.

## 12.8 `curl` - HTTP 응답 확인

HTTP 서버의 응답 헤더를 확인한다.

```bash
curl -I http://192.168.3.112:8080
```

웹 서비스나 관리 콘솔의 HTTP 응답을 확인할 때 사용할 수 있다.

## 12.9 `traceroute` - 네트워크 경로 확인

목적지까지의 네트워크 경로를 확인한다.

```bash
traceroute 192.168.3.112
```

명령어가 설치되어 있지 않거나 중간 장비에서 응답을 차단하는 경우에는 결과가 제한될 수 있다.

# 13. 로그 확인 및 분석

로그는 시스템이나 애플리케이션에서 발생한 이벤트와 오류를 기록한 파일이다.

장애가 발생하면 오류 메시지와 발생 시각을 확인하고, 해당 시점 전후의 로그를 분석해 원인을 파악할 수 있다.

## 13.1 `tail -f` - 실시간 로그 확인

```bash
tail -f application.log
```

로그 파일에 추가되는 내용을 실시간으로 확인한다.

## 13.2 `grep` - 오류 메시지 검색

```bash
grep -in "ERROR" application.log
grep -in "ORA-" application.log
grep -in -C 5 "ORA-" application.log
```

Oracle 오류 코드나 애플리케이션 오류를 빠르게 검색할 수 있다.

SharePlex 로그에서 특정 오류를 확인할 때도 같은 방법을 활용할 수 있다.

```bash
grep -in "error" /경로/SharePlex로그파일
```

## 13.3 `journalctl` - 시스템 및 서비스 로그 확인

systemd 기반 Linux에서 서비스와 시스템 로그를 확인한다.

```bash
journalctl -xe
journalctl -u sshd
journalctl --since today -p err
journalctl --since "1 hour ago"
```

주요 옵션:

| 옵션 | 설명 |
| --- | --- |
| `-u` | 특정 서비스 로그 확인 |
| `-e` | 로그 마지막 부분으로 이동 |
| `-x` | 추가 설명이 제공되는 경우 함께 표시 |
| `--since` | 지정한 시점 이후의 로그 확인 |
| `-p err` | 오류 수준의 로그 확인 |

서비스 장애가 발생했을 때 관련 로그를 확인하는 데 활용할 수 있다.

## 13.4 `dmesg` - 커널 메시지 확인

커널에서 기록한 메시지를 확인한다.

```bash
dmesg -T
```

하드웨어, 메모리, 장치 및 커널 관련 문제를 조사할 때 활용할 수 있다.

## 13.5 로그 분석 시 확인할 사항

로그에서 오류가 발견되면 다음 사항을 함께 확인하는 것이 좋다.

- 오류가 발생한 정확한 시각
- 오류 발생 직전과 직후의 로그
- 관련 프로세스의 실행 상태
- 디스크 및 메모리 사용량
- 서버 간 네트워크 연결 상태

오류 한 줄만 확인하기보다 최초 오류와 이후에 발생한 연쇄 오류를 구분하는 것이 중요하다.

# 14. 서비스 상태 관리

systemd를 사용하는 Linux에서는 `systemctl` 명령어로 서비스 상태를 확인하고 관리할 수 있다.

## 14.1 `systemctl status` - 서비스 상태 확인

```bash
systemctl status sshd
```

## 14.2 `systemctl start` - 서비스 시작

```bash
sudo systemctl start sshd
```

## 14.3 `systemctl stop` - 서비스 중지

```bash
sudo systemctl stop sshd
```

## 14.4 `systemctl restart` - 서비스 재시작

```bash
sudo systemctl restart sshd
```

## 14.5 `systemctl is-enabled` - 자동 시작 설정 확인

```bash
systemctl is-enabled sshd
```

서비스가 시스템 부팅 시 자동으로 시작되도록 설정되어 있는지 확인한다.

서비스 중지나 재시작은 운영 중인 애플리케이션에 영향을 줄 수 있으므로 작업 전 영향 범위와 서비스 관리 절차를 확인해야 한다.

# 15. 압축 및 파일 전송

데이터베이스 서버를 운영하다 보면 로그 백업, 설정 파일 복사, 덤프 파일 전송 등의 작업이 필요하다.

## 15.1 `tar` - 파일 및 디렉터리 압축

여러 파일과 디렉터리를 하나의 아카이브로 묶거나 압축한다.

```bash
tar -cvf backup.tar backup_dir/
tar -czvf backup.tar.gz backup_dir/
tar -tvf backup.tar
tar -xzvf backup.tar.gz
```

주요 옵션:

| 옵션 | 설명 |
| --- | --- |
| `-c` | 아카이브 생성 |
| `-x` | 아카이브 해제 |
| `-v` | 처리 과정 출력 |
| `-f` | 아카이브 파일 지정 |
| `-z` | gzip 압축 사용 |
| `-t` | 아카이브 내부 목록 확인 |

## 15.2 `gzip` - 파일 압축

파일을 gzip 형식으로 압축한다.

```bash
gzip application.log
gzip -d application.log.gz
```

일반적으로 압축 시 원본 파일은 `.gz` 파일로 대체된다.

## 15.3 `scp` - 서버 간 파일 전송

SSH를 이용해 로컬과 원격 서버 간 파일을 전송한다.

로컬 파일을 원격 서버로 전송하는 경우:

```bash
scp backup.dmp oracle@192.168.3.112:/home/oracle/
```

원격 서버의 파일을 현재 디렉터리로 가져오는 경우:

```bash
scp oracle@192.168.3.112:/home/oracle/backup.dmp .
```

Oracle Data Pump로 생성한 덤프 파일을 다른 서버로 이동할 때도 활용할 수 있다.

파일 전송 시에는 대상 서버의 IP, 사용자명, 경로 및 권한을 확인해야 한다.

# 16. 운영 업무에서 자주 사용하는 명령어 조합

개별 명령어뿐 아니라 여러 명령어를 조합하면 작업을 더 효율적으로 수행할 수 있다.

## 16.1 로그에서 오류 검색

```bash
grep -in "ERROR" application.log
```

대소문자를 구분하지 않고 ERROR가 포함된 줄을 검색한다.

## 16.2 로그 마지막 100줄 확인

```bash
tail -n 100 application.log
```

최근 로그를 빠르게 확인할 수 있다.

## 16.3 오류 로그 실시간 확인

```bash
tail -f application.log | grep --line-buffered -i "error"
```

로그가 추가될 때 ERROR가 포함된 줄을 실시간으로 확인한다.

## 16.4 디스크 사용량 확인

```bash
df -h
du -sh /home/oracle/*
```

파일시스템의 전체 사용량과 하위 디렉터리별 사용량을 함께 확인한다.

## 16.5 특정 프로세스 확인

```bash
ps -ef | grep '[o]ra_pmon'
```

Oracle PMON 프로세스가 있는지 확인한다.

## 16.6 특정 포트 확인

```bash
ss -lntp | grep 2100
```

해당 포트에서 대기 중인 TCP 소켓이 있는지 확인한다.

## 16.7 파일 검색 후 오류 확인

```bash
find /home/oracle -type f -name "*.log"
grep -in "ORA-" /home/oracle/application.log
```

첫 번째 명령어는 로그 파일을 찾고, 두 번째 명령어는 지정한 로그 파일에서 Oracle 오류를 검색한다.

# 17. Oracle 및 SharePlex 서버 운영 시 활용

Linux 운영 명령어는 데이터베이스와 데이터 복제 솔루션을 관리할 때도 자주 사용한다.

예를 들어 Oracle 또는 SharePlex에서 오류가 발생했다면 다음과 같이 점검할 수 있다.

## 17.1 서버 디스크 확인

```bash
df -h
df -i
```

데이터 파일, 로그, 아카이브 로그 등이 저장된 파일시스템의 사용률과 inode 상태를 확인한다.

## 17.2 프로세스 확인

```bash
ps -ef | grep -i oracle
ps -ef | grep -i shareplex
```

Oracle 및 SharePlex 관련 프로세스의 실행 여부를 확인한다.

## 17.3 포트 확인

```bash
ss -lntp | grep 2100
```

SharePlex에서 사용하는 포트가 LISTEN 상태인지 확인한다. 실제 설정된 포트 번호를 기준으로 점검해야 한다.

## 17.4 로그 오류 검색

```bash
grep -in "error" /경로/로그파일
grep -in "ORA-" /경로/로그파일
```

로그에서 오류 메시지를 검색한다.

## 17.5 파일 권한 확인

```bash
ls -l /경로/파일명
stat /경로/파일명
```

파일의 소유자, 그룹, 권한 및 상세 정보를 확인한다.

덤프 파일을 생성하거나 로그 파일을 기록하는 작업에서 권한 문제가 의심될 때 활용할 수 있다.

## 17.6 제품별 상태 확인

Linux 명령어는 서버와 OS 상태를 점검하는 데 사용하고, 제품별 명령어는 애플리케이션의 동작 상태를 확인하는 데 사용한다.

예를 들어 SharePlex의 Capture, Read, Export, Import, Post 상태와 복제 지연은 `sp_ctrl`의 관련 명령어를 함께 사용해 확인해야 한다.

Linux 명령어만으로 모든 데이터베이스 또는 복제 상태를 판단할 수 있는 것은 아니다.

# 18. 장애 발생 시 점검 순서

Linux 서버에서 장애가 발생하면 무작정 프로세스를 재시작하기보다 시스템 상태부터 순서대로 확인하는 것이 좋다.

## 1단계. 서버 상태 확인

```bash
hostname
uptime
date
timedatectl
```

서버 정보, 부하, 현재 시간 및 시간 동기화 상태를 확인한다.

## 2단계. CPU 및 메모리 확인

```bash
top
free -h
vmstat 1
```

CPU 사용률, 메모리 부족 여부, Swap 사용 및 시스템 부하를 확인한다.

## 3단계. 디스크 확인

```bash
df -h
df -i
du -h --max-depth=1 /home
```

디스크 공간이나 inode가 부족하지 않은지 확인한다.

## 4단계. 프로세스 확인

```bash
ps -ef
ps -ef | grep -i oracle
ps -ef | grep -i shareplex
```

필요한 프로세스가 실행 중인지, 특정 프로세스가 자원을 과도하게 사용하는지 확인한다.

## 5단계. 네트워크 확인

```bash
ip addr
ip route
ss -antp
nc -zv 대상IP 대상포트
```

네트워크 인터페이스, 라우팅 및 TCP 연결 상태를 확인한다.

## 6단계. 로그 확인

```bash
tail -n 200 /var/log/messages
grep -in "error" /var/log/messages
journalctl --since today -p err
```

오류가 발생한 시각과 전후 로그를 확인해 원인을 분석한다.

모든 장애가 동일한 순서로 해결되는 것은 아니지만, 위 절차를 활용하면 서버 자원 부족, 프로세스 이상, 네트워크 문제, 시스템 오류 등을 단계적으로 구분할 수 있다.

# 20. Linux 명령어를 익혀야 하는 이유

Linux 명령어는 단순히 파일을 관리하는 용도로만 사용되지 않는다.

서버 운영에서는 프로세스, 디스크, 메모리, 네트워크, 로그를 확인하는 작업이 반복적으로 발생한다.

특히 데이터베이스 서버를 운영할 때는 다음 명령어를 우선적으로 익히는 것이 좋다.

- `ps`, `top`: 프로세스 및 자원 사용 현황 확인
- `df`, `du`, `free`: 디스크 및 메모리 점검
- `tail`, `grep`, `journalctl`: 로그 분석
- `ss`, `nc`: 포트 및 네트워크 연결 확인
- `chmod`, `chown`: 파일 권한 및 소유권 관리
- `tar`, `scp`: 파일 압축 및 서버 간 전송
- `timedatectl`: 서버 시간 및 동기화 상태 확인
- `systemctl`: 서비스 상태 확인 및 관리

명령어의 사용법뿐 아니라 각 명령어가 어떤 상황에서 필요한지 이해하는 것이 중요하다.
